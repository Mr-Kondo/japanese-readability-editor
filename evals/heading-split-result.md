# 話題を並べた見出しを、本文が別々なら分ける規則の評価(#174)の結果

## 結論

新版(規則・SKILL.md の節・例34)を、採用する。事前に固定した6つの基準を、2回の記録を合わせて満たした。ただし、基準4のモード C の項は、1回目の数え方では満たさず、数え方を直して測り直した結果で満たした(下の「基準の判定」)。

この規則が効くことは、この合成9本で確かめた。旧版は、本文が別々の話題の見出しを、9出力のうち0件しか分けなかった。新版は、9件すべてを分けた。一方、比較・使い分け・1組の語・見出しの文言の指定・モード C・曖昧な語の見出しでは、新版も分けなかった。意味・数値・条件の欠落は、新版の27出力で0件だった。実文書での頻度や効果は、測っていない。

基準4の経緯。1回目では、新版の h08 で「空白を除いて原文と同一」が2 / 3だった。原因は、e016 が末尾に報告の1段落を足したことである(旧版の e015 も、余分なコードフェンスを足して2 / 3だった)。計画の数え方が、報告や記号が末尾に付く出力を想定しておらず、規則の効果ではなく体裁を測っていた。そこで、結果を見たあとに数え方を直し、h08 だけを新しい出力で1回だけ測り直した。2回目の新版は、3 / 3で見出しも原文も変わらず、付け足しは報告だけだった。数え方を結果のあとに直した点は、この判定の弱さである。1回目の判定は、記録のとおり残す。

## 読んだこと

- **分けた出力**(新版 h01〜h03 の9件)。文の言い回しは変えず、見出しだけを「ログについて」「設定について」のように分けた。h02 は、後ろの見出しを「4. 問い合わせ」(2件)または「4. 不明な点の問い合わせ先」(1件)へ振り直した。後者のような見出しの具体化は、旧版にも見られた。h03(1段落に入り混じった文)は、「予約」の3文と「キャンセル」の2文にまとめ直し、5文とも残った。
- **分けなかった出力**。h04(違い)・h05(使い分け)・h06(「検索と置換」)・h09(「関係」)は、新版も旧版も、見出しを1つに保った。見出しの文言は、末尾の「について」が削られた出力がある。h05 は旧版・新版とも全件(各3件)、h04 は新版の1件、h09 は旧版の3件である。h06 は両版とも、h04 は新版の2件、h09 は新版の3件は、文言も原文と同じだった。
- **h09 の冒頭の文**(判定には使わない)。旧版・新版とも、3件すべてで、予告の文「ここでは…説明する」を削った。見出しの直後の文が関係の中身を言い切っていたのは、旧版 0 / 3、新版 1 / 3(e054「親ジョブと子ジョブは、起動、失敗、停止の面で結びついている。」)だった。曖昧な語の見出しの直し方(冒頭の文で言い切る)は、1件の差で、効果は確かめられていない。
- 旧版も、「見出しの具体化」の規則で、見出しの語を変える出力があった(h02 の「概要」→「勤怠システムの使い方」など)。話題を分けることは、旧版では起きなかった。

## 限界

- 合成した9本の短い文書で、実文書での頻度・効果を表さない。3回の反復は、独立した27種類の文章ではない。
- 出力は本文だけを返させる条件で、「直さずに報告する」(h07、判断がつかない1組の語)と、番号の振り直しで壊れる参照の報告は、h08 の1件を除いて測れていない。h02 には、参照を入れていない。
- 分ける・分けないの判定は、見出しに話題の語が入っているかによる。意味の保持は、人(実行者)が読んで決めた。別の採点者による盲検の採点はしていない。
- モデルは `sonnet`(medium)の1つだけで、ツールを使えない条件で、スクリプトによる照合を含まない。
- 比較・使い分けの見出しを分けないことは、各1本で確かめた。本文が比較に見えて別々の話題である、のような境界の事例は、測っていない。
- 実利用での効果の確認は、この評価と分ける。
- Issue #174 の本文は、追加する例を「例26」と書いたが、実際は例34である(最後の例が33だったため)。計画では、生成の前に訂正した。
