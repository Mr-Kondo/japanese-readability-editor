# 話題ごとの割り当ての照合：効果検証の結果（Issue #218）

## 結論

新版（話題ごとの割り当てを組ごとに照合する規則）は採用しない。実行時のスキルは v0.25.1 のままとする。
[計画](assignment-swap.md)の基準の確認で止まった。旧版の S 群（入れ替わりやすい推敲）18出力で、入れ替わりは0件だった。基準は3件以上なので、直すべき失敗が観測されておらず、新版の効果は測れない。
この判断は「観測された失敗がない」ことによるもので、新版が無効だという証明ではない。

## 比較条件

[計画](assignment-swap.md)とケース・実行コードを変えず、12ケース×3回×2版の72出力を完了した。計画を固定したコミットは 639d688。
旧版は main（9b80856）、新版は旧版に[差分](assignment-swap-run/candidate.diff)（規則の節、チェック1行、`SKILL.md` の1句、例1つ）を足したもの。
実行モデルは全件 `claude-sonnet-5-5`。費用は4.918ドル。
版を伏せた通し番号（b01〜b72）で、72出力すべてを人が読んだ。判定は swap / ok / unclear の3つ。

## 結果

| 群  | 版   | 出力数 | 入れ替わり |  ok | unclear |
| --- | ---- | -----: | ---------: | --: | ------: |
| S   | 旧版 |     18 |          0 |  18 |       0 |
| S   | 新版 |     18 |          0 |  18 |       0 |
| R   | 旧版 |      9 |          0 |   9 |       0 |
| R   | 新版 |      9 |          0 |   9 |       0 |
| C   | 旧版 |      9 |          0 |   9 |       0 |
| C   | 新版 |      9 |          0 |   9 |       0 |

欠落は旧版・新版とも0件だった。自動判定の「作り足し」は旧版の2件（R 群の「2文」、C 群の「1文」を数値と数えたもの）で、事実の作り足しではない。
「余計な注記」の語の増加は、S 群で旧版3・新版5、R 群で旧版2・新版1、C 群で旧版1・新版1。多くは「照合スクリプトを実行していない」という報告の「照合」に当たったもので、割り当てへの指摘ではない。基準は旧版の入れ替わりが3件未満の時点で満たされないため、この差は採否に使っていない。

## 読み取れること

- 旧版は、2組の割り当てが並ぶ文（s01、s05、s06）、前者・後者（s02）、表への変換（s04）でも、組み合わせを保った。この範囲では、旧版の既存規則（構造を変えた箇所で主体・対象を保つ、入れ子の主体の照合）で足りている。
- 「それぞれ月曜と木曜に」（s03）は、旧版・新版とも、曜日の対応が決まらないとして原文のまま残した。割り当ての入れ替えではなく、原文の曖昧さへの対応である。
- 旧版でも、ケースは入れ替わりやすい形に寄せてある。それでも0件なので、実際の推敲で頻度が高いとは言えない。

## 限界

- 自作の短い文12本で、実際の推敲での頻度は未確認である。効果は人工例の範囲の話に限る。
- 入れ替わりは人が読んで判定した。読み手の見落としはありうる。版は伏せたが、ケースの種類は見えていた。
- `sonnet`・ツールなし・1回の生成の範囲である。他のモデルや、長い文書の推敲では確かめていない。
- 上流の検出器の要否は、この評価では決めていない。regex 解析の `compare_rewrite.py` が、入れ替わりを候補に出さないことは、Issue 本文の実測のまま変わらない。

## 再検討の条件

実際の推敲で、話題ごとの割り当ての入れ替わりが報告されたときは、その例を評価セットへ戻して再評価する（フィードバックの扱いは `docs/feedback.md`）。
