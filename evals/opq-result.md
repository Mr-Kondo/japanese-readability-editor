# OPQ（目標・問題・疑問）から結論を決める規則の比較結果（見送り）

仮説・成功指標・撤退条件は [ADR](../adr/2026-11-11-opq-analysis.md) に、実行前に書いた（ADR のハッシュは各 `run.json` の `adr_sha256`）。ケースは [実験1の11件](opq-cases.json)、[実験2の15件](opq2-cases.json)。実行記録と生の出力は [opq-run/](opq-run/)（実験1）、[opq2-run/](opq2-run/)（実験2）にある。

## 結論

**規則は足さない。** 「結論・依頼を冒頭に置く」効果は2回とも観測できたが、事前に決めた意味保持の指標を、2回とも満たさなかった。

| | 旧版 | 候補版 | 候補版2 |
|---|---|---|---|
| 冒頭配置（実験1、主6ケース18出力） | 8/18 | 18/18 | — |
| 冒頭配置（実験2、主9ケース27出力） | 17/27 | — | 25/27 |
| 意味保持（実験1、33出力） | pass 31、fail 1、uncertain 1 | pass 29、fail 4 | — |
| 意味保持（実験2、45出力） | pass 43、fail 1、uncertain 1 | — | pass 40、fail 4、uncertain 1 |
| ペア判定 answer_first（実験2） | 勝ち0 | — | 勝ち15、tie 10、uncertain 7 |
| 変えない対照・制約の違反 | 0 | 0 | 0 |

- 実験1のペア判定は、判定の後ろに説明文が付いてパースに失敗し、実行できなかった（`execution_failed`）。実験2では、パースを直して全ペアをやり直した。
- 候補版2の fail 4件は、順序の入れ替え自体を構成の変更とみなした判定が2件（o03、n02）、評価の足し（o05「減少幅が広がっています」）と、確認計画の足し（n03）が各1件。評価の足しは、禁止の文を足した後も再発した。
- 実験2の新規 n01〜n03 は、原文自身が冒頭の判定を満たしていて、判別力がなかった。冒頭配置の差は、規則の調整に使った o01〜o06 だけで生じた。独立した検証とは言えない。

## 前の検証（節で一つのメッセージ）との違い

前の検証は、旧版も候補版も、混在した節を分けなかった（モードBでは、見出しの分割に踏み込まない）。今回は、モードBが許す「順序の入れ替え」と、モードAを対象にしたため、行動が変わった。つまり、先行研究に支持されるかどうかより、モデルが既定で踏み込む操作かどうかが、効き方を決めたように見える（推測。操作の種類を変えて比べた実験はしていない）。

## 実行条件・限界

- 旧版: `b589a94`（スキルは v0.22.0）。`sonnet / medium`、ツールなし、新しい文脈。実験2の旧版の o01〜o11 は、実験1の出力を再利用した（スキルと指示のハッシュ一致を確認）。実モデル識別子は全呼び出しで `claude-sonnet-5-5`。
- 実験1の途中で、`runner.py` の対照の判定の不具合を直した（旧版の生成後、候補版の生成前）。内容は `opq-run/run.json` の `amendments` にある。
- 意味保持の指標は、実験2で、旧版の fail が1件あるため、「全件 pass」から「旧版以下」に変えた。実験1の結果を見た後の変更で、ADR に明記した。
- 順序の判定（o08、o11）は、先頭の語と後ろに置く語の前後だけを見る。他の順序違反を見逃しうるため、「違反0」は弱い保証である（Codex のレビューの指摘）。
- ペア判定の勝敗は、左右反転の2回の判定が一致したものだけを数え、不一致は uncertain とした。
- 自作ケース、同じモデル系統の採点、人間の採点なし、3反復は独立ではない。冒頭配置は代理指標で、人間の読者の理解度は未計測。
- 費用は、API 換算で、実験1が約4.8米ドル（記録された74呼び出し。パースに失敗した1回の費用は含まない）、実験2が約4.7米ドル（再利用した旧版の出力を除く80呼び出し）。各 `run.json` の `cost_usd` の合計。

## 利用者の判断に残すこと

1. 意味保持の判定で、依頼を冒頭へ寄せる順序の入れ替えを許す基準に変えて、事前登録し直し、再評価するか。
2. 規則を足さず、明示的に「結論を先に」と頼まれたときだけ冒頭へ寄せる、今の運用にとどめるか。
3. 評価の足しの癖を、別の方法（モード A の素材の書き方など）で抑えられるかを検証するか。
