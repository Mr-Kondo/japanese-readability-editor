# 確認応答を短くする候補の評価結果

## 文脈

[Issue #216](https://github.com/Mr-Kondo/japanese-readability-editor/issues/216)の追加評価です。
[事前計画](jaist-ambiguity2.md)と[自作10ケース・採点点検7件](jaist-ambiguity2-cases.json)に従い、現行版と候補版を各30回生成した。
初回とはケースと採点軸が異なるため、結果を合算しない。
現行版は v0.25.1、ソースコミットは `8f9bfe8` です。候補は未公開の作業用変更であり、版は上げていない。

**質問応答を短くできる余地は確認できた。ただし、候補は事前条件に届かず採用しなかった。**
本結果の「失敗」は事前の長さ基準への不適合であり、人が読みにくいと判断したことではない。

## 核心的な論理

### 証拠

| 項目                    | 現行版                   | 候補版                      |
| ----------------------- | ------------------------ | --------------------------- |
| 生成                    | 10ケースを各3回、30出力  | 同じ10ケースを各3回、30出力 |
| 単純な確認4ケースの出力 | 12件                     | 12件                        |
| 対象の文字数の中央値    | 289.5文字                | 49文字                      |
| 対象の最小〜最大        | 183〜452文字             | 36〜212文字                 |
| 対象の180文字超         | 12/12件                  | 1/12件                      |
| 意味保持・Codex         | 30/30件 pass             | 30/30件 pass                |
| 課題達成・Codex         | 30/30件 pass             | 30/30件 pass                |
| 意味保持・独立採点      | 30/30件 pass             | 30/30件 pass                |
| 課題達成・独立採点      | 29件 pass、1件 uncertain | 30/30件 pass                |
| 生成時間                | 77.62秒                  | 61.72秒                     |
| 生成のAPI換算費用       | 2.0308108米ドル          | 1.9970488米ドル             |

両版とも実行モデルは `claude-sonnet-5-5`、Claude Code CLI 2.1.330、effort medium、ツールなしです。
生成のAPI換算費用は合計4.0278596米ドル、独立採点6呼び出しは0.232006米ドルだった。
計画・候補・最終結果のレビュー費用は、この独立採点費用に含めない。いずれも追加請求額とは区別する。

文字数は応答全体を `len(text.strip())` で数え、改行、注記、仮案も含めた。
中央値は約83.1%減った。
ただし、候補の q03・2回目が212文字で、全12出力を180文字以内にする条件を満たさなかった。
40%以上の短縮と、全件180文字以内は別の条件です。前者だけで採用しない。
生成時間は、送信直前から全出力の回収までの経過時間です。同時最大3件の並列実行を含む。

採点点検7件の両軸14判定は、事前期待値と独立採点がすべて一致した。
全60出力と7点検を混ぜ、版名、Codexの判定、点検の期待値と説明を隠して無作為に並べた。
独立採点は全67件を返し、欠測や重複はなかった。
Codexも全件を確認し、引用と個別の理由を残した。Codexには版が見えるため、完全な二重盲検ではない。

### 仮説と実際の変更

現行版では、必要な質問の後に仮案や作業予定を添えるため、応答が長くなると考えた。
候補は参照規則の1段落と配送方法の確認例1節だけです。
質問だけで必要な確認を伝えられる場合は質問だけを返し、説明が必要な場合は必要な読み方を示す内容にした。
文字数の上限は実行規則に入れなかった。

比較する各対象の確認事項をそろえる規則も検討したが、今回の現行版では確認漏れが再現しなかった。
実装前レビューの指摘に従って、その規則は候補から外した。
確認漏れの改善まで実証したとは扱わない。
規則と例を同時に変えたため、それぞれの効果は分離できない。

### 反論と採否

1件の超過だけで候補を見送る条件は厳しく、実用的な短縮を過小評価する可能性がある。
180文字と40%減は探索上の判断値であり、読みやすさの実証値ではない。
別の条件なら採否が変わりうるが、結果を見て今回の条件を緩めなかった。
単一の候補を1回だけ比較したため、残った超過が確率変動か規則の不足かは切り分けられない。

## 重要ポイント

- 長さについては、現行版の事前基準への失敗を確認してから候補を作った。
- 候補30件では、意味保持と課題達成は両採点者が全件 pass とした。実利用の正しさを保証する結果ではない。
- 現行版 c06・3回目の課題達成は、Codexが pass、独立採点が uncertain だった。不一致を残し、全件一致とは扱わない。
- c06 の不一致は、必要な9項目は尋ねているが、条件付きの代替本文まで示すことが「不足情報だけの確認」を逸脱するかという点にある。
- 条件未達の候補は戻した。版、配布物、Macの導入先は変更していない。

## 具体例

比較の q01 は、両プランの費用と利用上限の有無を尋ねる内容です。
必要な4項目を残したまま、現行版の217〜276文字から候補版は各49文字になった。
無料の対象を確認する q03 は、候補版でも97、159、212文字とばらついた。
短縮は進んだが、説明を添える挙動が残り、安定して短いとはいえない。

## 平易な説明

わかりやすく言うと、必要な質問を残して説明を短くする余地はあるが、今回の候補は毎回短くする約束までは守れなかったということです。

## 限界と信頼度

同じ自作ケースを失敗確認と比較に使っており、未使用事例への一般化は確認していない。
追加例は配送が題材で、評価例の文・固有名・数値は転載していないが、比較の構造は近い。
q01の候補3出力は同文で、追加例と同じ質問の型になった。異なる構造への転用は未確認です。
対象はモード B の短文10例だけです。実利用、人の採点、他モデル、スキルなしとの比較は未検証です。
導入済みスキルの自動読み込み、確認後の回答反映、説明や仮案が必要な複雑な課題も検査していない。
CLIで固定できないサンプリング条件は不明です。同じモデルによる生成と採点にも限界がある。

短縮を確認したという限定した結論の信頼度は0.9、一般の文章で有用という結論の信頼度は未評価です。
数値は主担当の主観的な確信であり、統計的な確率ではない。
追加の規則の維持費を払う前に一度で終了する計画に従い、別候補の試行は行わなかった。

## 結論と検査記録

改善の余地を否定する結果ではない。短縮という仮説を支持する生成結果が得られた。
ただし、事前条件を満たさないため、この候補は採用しない。
実行時2ファイルは現行版へ戻し、評価資料だけを残す。

| 検査・レビュー   | 記録                                                                                                   |
| ---------------- | ------------------------------------------------------------------------------------------------------ |
| 計画とケース     | Claude Codeで2回確認。初回 revise の指摘へ対応し、2回目は生成前の旧処理確認を条件に proceed            |
| 実装前           | 長さ基準への失敗と候補を確認。比較情報の規則を外せば proceed という判断に従って実装                    |
| 独立採点         | claude-sonnet-5-5、effort medium。全67件を6組で確認。点検14軸はすべて一致                              |
| 入力と出力       | 全60件の重複なし。実入力3ファイル・全プロンプトのハッシュと生出力の一致を確認                          |
| 比較条件         | CLI、モデル、引数、共通指示、ケース、計画、実行処理とラッパーのハッシュが両版で一致                    |
| 変更範囲         | 両版で変わったスキルファイルは参照規則と例の2ファイルだけ。復元後は実入力3ファイルが現行版と一致       |
| 最終結果レビュー | Claude Code、claude-sonnet-5-5、effort medium。段階3・4とも重大指摘なし、proceed。軽微な文書指摘に対応 |
| Markdown         | 新規計画と結果の整形・文法・日本語校正は成功。一覧のtextlintは既存の8件が残る                          |

候補の実行時2ファイル全体へのMarkdown検査は不合格だった。
追加例にも漢数字と助詞の指摘があり、採用する場合は修正が必要です。
今回は候補を戻したため、これらを修正済みとは扱わない。
初回に実施した評価処理の既存11テストは成功。今回、既存処理のコードは変えず、保存先と入力の差し替えを自己検査した。

詳細な出力、凍結した両版の本文、採点、初回判定、レビュー入力と結果は、Git管理外の `feedback/jaist-ambiguity2/` に保存した。
ローカルの実行用スクリプトも再確認のために残す。
追跡対象は計画、ケース、結果、評価一覧の4ファイルに限る。最終レビュワーは提示資料だけを確認し、実ファイルを再検証していない。
初回の資料と無関係な変更は保持する。公開PR、マージ、リリースは未実施です。
