# 認知負荷5項目（比較・探索・推測・要約・暗算）の効果検証の計画

実行の前に固定する計画。結果は [cognitive-load-result.md](cognitive-load-result.md) に記録する。結果を見てから、この計画を変えない。変えるときは、理由と日付を残し、変更前の結果を残して、新しい記録として実行し直す。

## 問い

貼られた5項目を規則に足すと、(1) 読み手の作業が減るか、(2) 意味が欠けない・作り足さないか。足す規則は、旧版と同じ条件で比べる。

## 現行規則との照合

| 項目 | 現行の規則 | この回で測るか |
|---|---|---|
| 結論を先に | rules の「内容と論点の整理」「長すぎる段落」ほか | 件数と種類（C）のみ測る |
| 指示語・前提・条件 | 「意味を確かめてから直す場合」「指示語」 | 重複のため測らない |
| 不足を問う・指摘する | 「意味を確かめてから直す場合」 | 測る（E） |
| 差分・比率・合計を計算して示す | なし | 測る（A） |
| 依頼・期限を目立たせる | なし | 測る（B） |
| 件数と種類を先に | なし | 測る（C） |
| 比較の並べ方・共通は一度 | なし | 測る（D） |
| 事実・判断・依頼・未確認の区別 | なし | 測る（F） |
| screenshot の着目箇所、graph の結論 | なし | 文字では測れない。未測定 |
| 揶揄しない | なし | 測らない（測るには揶揄の入力が要り、貼られた「test data にも不適切な表現を使わない」と矛盾する）。未測定 |

## 比較

- 旧版: e95b218 のクリーンな worktree の skill。
- 新版: 旧版に、`readability-rules.md` の節「読み手にさせない作業」と、`SKILL.md` の1行を足したもの。ほかは同じ。
- 呼び出しは既存の評価と同じ（`evaluate_readability.py` の `invoke`、モデル `sonnet`、ツールなし。スキルの3ファイルを貼る方式）。1ケース3回。

## 入力

[cognitive-load-run/cases.json](cognitive-load-run/cases.json) の26本。自作の短い文。

| 群 | 本数 | 内容 |
|---|---:|---|
| A 計算 | 4 | 数値が散らばり、差・合計が判断に要る |
| B 依頼・期限 | 3 | 依頼や期限が埋もれている |
| C 結論・件数 | 3 | 結論が最後、または件数が先にない |
| D 比較 | 3 | 2案の同じ記述が重なり、差が埋もれている |
| E 不足 | 4 | 対象・範囲・数値・条件・期限のどれかが原文にない（依頼は「本文だけ」を付けない） |
| F 区別 | 2 | 事実と判断と未確認が混ざる |
| control | 7 | 作り足してはいけない例（整った文2、期限なし1、概数1、数が足りない1、完全な情報1、整った短文1） |

26本 × 3回 × 2版 = 156出力。

## 数え方（生成の前に固定）

各出力に、`runner.py --count` の決定的な確認をかける。基準はケースごとの `checks`（cases.json）に書いた。

- 作り足し: 出力の数値が、原文の数値、`allowed_derived`、`derive_ok` が真のケースでは原文の数値から作れる和・差・積・商・百分率のいずれでもない。または `forbid_patterns` の一致のうち、原文にない一致がある（原文の同じ語は数えない）。
- 混入: 依頼が「本文だけ」のとき、出力の質問・注記の語の数が、原文より多い。
- 意味の欠落: `must_keep` の語が出力にない。
- 効果あり: ケースごとの `expect_any`、`expect_within`（冒頭 N 字に語がある）、`max_count`（共通語が1回以下）、`gap_groups`（不足の指摘が k 群以上）のいずれかを満たす。
- 余計な指摘: control の完全な情報の例で、出力が不足を指摘する。

A群の誤計算（作れる値の取り違え）は決定的確認で拾えない。A群の効果ありは、人が読んで計算の正誤を確かめてから数える。k02 は、差（4）を示すことを作り足しにしない（原文の2数の差であり、必須ではない）。決定的確認は、原文をそのまま出力とみなして自己検査済み（作り足し・混入・欠落・効果あり、いずれも0件。不足の指摘の語群も原文に一致しない）。2026-11-21、レビュー（Antigravity）の指摘で、判定の穴（原文に1語あると禁止語全体が無効、派生値の不足、指摘の語群が原文に一致）を直した。2回目のレビューで、正しい派生値（a03 の 24、a02 の 76、c01 の 5）を許可値に足した。

## 読み方（事前に決める）

項目ごと（A〜F）に決める。

- 採用候補: 新版の効果ありが、旧版より3件以上多く、かつ、新版の作り足し・混入・意味の欠落が、旧版より増えない。かつ、control で新版の作り足し・混入・余計な指摘が、旧版より増えない。
- 不採用: 上記のどれかを満たさない。作り足しは1件でも増えたら不採用。
- 件数はそのまま並べる。確率や一般化は主張しない。
- 決定的確認で拾えない事項（D・F の読みやすさ、意味保持の細部）は、効果の候補だけを人が読んで確かめる。人が読んで決めた分類は、結果に引用付きで分ける。モデル採点は、この回では使わない。
- この計画では、規則を `main` に足さない。足す判断は別の Issue で、結果に基づく。

## 費用

実行は `claude -p` で、ログイン中のサブスクの枠を使う（API の課金はない）。結果の `cost_usd` は API 換算の参考値で、10ドルを超えそうなら止めて報告する。枠の上限に当たったら、止めて再開する。使用量は未測定。

## 限界

- 自作の短い文で、実文書の頻度を表さない。
- 3回は独立な156種類の文章ではない。
- 決定的確認は、文字列に基づく。読みやすさの判断ではなく、効果の候補を数えるだけで、D・F の効果は人が読んで確かめる。
- 評価例の結果は、実利用の効果の証明ではない。
