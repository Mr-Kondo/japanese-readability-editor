# 意味保持の失敗への修正と再評価

2026-10-16。**確認したケースでは意味保持の失敗は再発しなかった。** 修正後のモデル採点は、従来12ケース×3回の36出力と、追加6ケース×3回の18出力で全合格。ただし、一般的な意味保持の保証や読みやすさの改善を確認した結果ではない。

## 原因と修正

- 「設定の変更」を「設定を変更した内容」にすると、原文で未確定の完了状態を補ってしまう。動詞にするために完了・予定・主体を補う場合は名詞を残し、「確認の実施」など周囲を整理する手順にした。同じ関係・状態・評価と確認できない部分は元に戻す。
- 「支える→保つ」の失敗判定には解釈の余地があるが、寄与と維持は異なる読みを生みうる。例集の「最大3回まで再試行することで、可用性を保ち…」を「最大3回まで再試行する仕組みが、可用性を支え…」に修正し、元の評価を担う述語を残した。
- 例26に、状態が不明な「変更」を名詞のまま保って周囲だけ直す例と、完了を補う誤った修正を追加した。確定した完了状態まで曖昧に戻す指示にはしていない。

## 同条件の再比較

修正前は[初回評価](readability-model-run.json)のafter版、修正後は今回の3ファイルのSHA-256で特定した版。初回評価のbefore版とは区別する。

モデル・設定・入力・生成指示・採点基準は初回と同じで、全生成・採点の実モデルは `claude-sonnet-5-5`、指定は `sonnet / medium`。版の実行順を交互にし、新しい文脈で各3回生成した。各呼び出しは12ケースを一括処理した。版名を伏せ、左右と提示順を無作為化して別文脈で採点した。採点指示の変更は総件数の36→54だけである。

| 従来12ケースの意味保持（モデル採点） | pass | fail | uncertain |
|---|---:|---:|---:|
| 修正前 | 33 | 3 | 0 |
| 修正後 | 36 | 0 | 0 |

修正前には、評価の置換、変更履歴の創作、確認対象を変更内容から変更の有無へ狭める出力があった。修正後のr03では3回とも「設定の変更を確認する必要があります」、r07では3回とも元の「品質を支え…信頼性を高めます」を保った。

両版が意味保持に合格した33組の読みやすさは、修正後の1勝・4敗・28同点。残る3組は意味保持不合格により比較から除外した。**意味保持の確認は通過したが、読みやすさを含む全体の採用判断は保留**とする。意味保持の成功だけで事前の採用基準を変更しない。

## 追加6ケース

[追加ケース](readability-preservation-cases.json)は、今回の修正後、生成前に固定した。出力を見てからの指示調整には使っていない。

- 状態不明の変更を、変更済み・変更予定と決めない。
- 明示された昨日の変更済み状態と、今日の確認を区別する。
- 来週の更新予定と、その翌日の確認予定を保つ。
- 「調査を支える」という寄与と、すべての誤りを発見できるわけではないという留保を保つ。
- 元から動作が明確な「温度を5℃に保つ」を残す。
- 資料を提出した人と、主体不明の確認・受付を混同しない。

修正後のみを各3回生成し、18/18が意味保持に合格した。名詞の連続を整理した出力も得られ、原文への全面的な復帰ではなかった。採点用の比較相手は原文そのものであり、旧版で生成した出力ではない。原文との読みやすさ比較は15勝・3同点だが、旧版に対する優位性の証拠にはしない。
