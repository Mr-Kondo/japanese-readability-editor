# 話題ごとの割り当ての照合（Issue 218）の効果検証の計画

実行の前に固定する計画。結果は assignment-swap-result.md に記録する。結果を見てから、この計画を変えない。

## 問い

新版（話題ごとの割り当てを組ごとに照合する1節・チェック1行・SKILL.md の1句・例1つを足したもの）は、旧版（main）より、推敲で話題ごとの割り当てを入れ替えることが少ないか。語順だけを変える推敲や、割り当てのない文で、余計な注記や内容の欠落を増やさないか。

上流（yomiyasu v3.4.0）の検出器は移植しない。検出器を作るかどうかは、この評価では決めない。

## 比較

- 旧版: main（9b80856）の skill。新版: 旧版に、[assignment-swap-run/candidate.diff](assignment-swap-run/candidate.diff) の変更を足したもの。
- 生成の指示は旧版・新版で同じ（runner.py の `GEN2`）。`sonnet`、ツールなし。1ケース3回。費用の上限は設けない（runner.py の `COST_CAP` は実質の無制限）。
- 例に使った名前・部署（総務部・経理部・第一・第二会議室）は、評価のケースに使っていない。

## 入力

[assignment-swap-run/cases.json](assignment-swap-run/cases.json) の12本。

| 群  | 本数 | 内容                                                                                                                   |
| --- | ---: | ---------------------------------------------------------------------------------------------------------------------- |
| S   |    6 | 入れ替わりやすい推敲。2つの割り当てが並ぶ文、前者・後者、それぞれ、表への変換、短文の統合、日をまたぐ逆の割り当て      |
| R   |    3 | 組み合わせを保つ推敲。語順を整えてよい依頼、同じ人が逆の役を持つ2組                                                    |
| C   |    3 | 割り当てがない文、話題が1つだけの文、人の列挙だけの文。1つは本文だけを求める依頼                                       |

12本 × 3回 × 2版 = 72出力。

## 数え方（生成の前に固定）

- 入れ替わり（swap）: 出力のなかで、ある話題に結び付いた人・ものが、原文の組（cases.json の `pairs`）と違う。S・R・C の全72出力を、版を伏せて人が読んで判定する。読み合わせ表は `--count` が、出力の並びを固定の乱数で混ぜ、出力 ID と無関係な通し番号（b01〜b72）を付けて作る。出力 ID は版の交互の順に並ぶので、表には出さない。判定は swap / ok / unclear の3つで、`labels.json` に保存する。人の判定は版の名前を見ずに行い、集計で初めて版に結び付ける。
- 欠落: `must_keep` の語が出力にない、または原文の数値が消えた。
- 作り足し: 原文にない数値が出力に出る。
- 余計な注記: 「割り当て・割当・入れ替わ・入れ替え・取り違・組み合わせ・照合」の語が、原文より多い。推敲のあとの指摘が通常の形で付くことは、数えない。
- unclear は、新版では swap に数え、旧版では数えない（新版に不利な向き）。unclear が全体で5件を超えたら、判定不能として採用しない。件数はそのまま並べる。

## 読み方（事前に決める）

1. 基準の確認: 旧版の S 群（18出力）の swap が3件未満なら、直すべき失敗が観測されていない。効果は測れないので、採用しない。理由は「観測された失敗がない」と書く。
2. 採用: 旧版の S 群の swap が3件以上で、新版の S 群の swap が旧版の半分以下。かつ、S・R・C のどの群でも、欠落と作り足しが新版で旧版より増えない（S 群の内容を削って入れ替わりを減らした出力を、改善に数えないため）。かつ、余計な注記が R・C 群で増えない。
3. 不採用: 上のどれかを満たさない。R・C 群で、旧版にない swap・欠落・作り足し・余計な注記が1件でも出たら不採用。
4. 件数はそのまま並べる。一般化は主張しない。

## 手順

1. 旧版・新版のスキルを用意し（旧版は main の detached worktree、新版はその複製に candidate.diff を適用）、`runner.py --base ... --cand ...` で記録を作る。ファイルの SHA-256 を記録し、生成後は計画・runner・ケースの変更を拒む。
2. `--generate` で72出力を作る。
3. `--count` で自動の数え方と読み合わせ表を作り、`labels.json` を書いて `--score` で集計する。

## 限界

- 自作の短い文12本で、実際の推敲での頻度の証明ではない。ケースは入れ替わりやすい形に寄せてあるので、旧版の swap 率は実際より高く出る恐れがある。
- 判定は人が読む。語群では組み合わせの正しさを決められないので、読み手の見落としがありうる。版は伏せるが、ケースの種類は見える。
- 新版は1行の手動照合で、検出器ではない。モデルが規則を実行せず、効果が出ないことはありうる。
- 上流の改善率は、こちらの効果の根拠にしない。
