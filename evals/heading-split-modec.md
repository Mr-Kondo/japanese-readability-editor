# 話題を並べた見出しの規則: モード C(h08)の測り直し(#174、2回目)の計画

実行の前に固定する計画。結果は `evals/heading-split-result.md` に、1回目の記録と並べて書く。1回目の記録([heading-split.md](heading-split.md)、[heading-split-run/](heading-split-run/))は変えない。

## 測り直す理由(2026-11-14)

1回目で、基準4の「h08 は文字も変わらない」を、文字どおりには満たさなかった。新版の3出力のうち、見出しと本文が原文と同じなのは3件だが、1件(e016)は、末尾に「モード C のため…モード B なら分ける候補です」という報告の1段落を足した。旧版の1件(e015)は、末尾に余分なコードフェンスを足した。

計画の数え方(空白と改行を除いて、出力が入力と同じ)は、報告や記号が末尾に付く出力を想定していなかった。SKILL.md は、モード C では「直したかった箇所を報告する」と定めている。新版の報告は、その動作の一つで、本文を変えていない。数え方が、規則の効果ではなく出力の体裁を測っていた。

結果を見てから数え方を変えると、結果に合わせた基準になりうる。そこで、1回目の記録の判定は変えず、数え方を直した上で、h08 だけを新しい出力で測り直す。測り直しは1回だけにする。結果がどうでも、再度は測り直さない。

## 変えないもの

- 入力: h08 の1本(`heading-split-run/cases.json` と同じ文章・依頼)。
- 旧版・新版のスキル3ファイル: 1回目の `run.json` に保存した全文を使う(ハッシュが同じ)。
- 生成の条件: モデル `sonnet`、推論 `medium`、ツール無効、本文だけを返す指示。各版3回(6出力)。

## 数え方(生成の前に固定する)

- 見出しが変わらない: 出力の見出しの並びが入力と同じ。
- 原文が先頭から変わらない: 空白と改行を除いた出力が、空白と改行を除いた入力で始まる。
- 末尾の付け足し: 原文の最後の文(「交換は、2年に1回の目安である。」)より後ろの文字。全件を人が読み、次の3つに分ける。
  - 報告: 直さなかった箇所や理由を述べる文。
  - 体裁: 区切り線・コードフェンスなど、文章でない記号。
  - 本文の変更: 原文にない文が、本文として足されている。

## 基準(事前に決める)

1回目の基準4の h08 の項を、次に置き換える。

- 新版の3出力すべてで、見出しが変わらず、原文が先頭から変わらず、末尾の付け足しが「報告」か「体裁」である(「本文の変更」が0)。

置き換え後に、1回目の6つの基準がすべて満たされれば、採用候補とする。満たされなければ、規則を入れない。旧版の件数も、そのまま並べる。

## 費用の上限

1.5ドル。見込みは約0.4ドル(1回目の1出力あたり約0.066ドル×6)で、測っていない。

## 限界

- 測り直すのは h08 の1本×3回で、モード C の挙動の一般的な確認ではない。
- 「報告」と「本文の変更」の分類は、人(実行者)が読んで決める。
- 1回目と同じく、別の採点者による盲検の採点はしない。
