# 長い下書きでの「ではなく」の発生の測り直し（#167、2回目）の結果

計画は [negation-contrast-long.md](negation-contrast-long.md)。実行記録は [negation-contrast-long-run/run.json](negation-contrast-long-run/run.json)（入力・生出力・数えた結果・実モデル・費用）。実行は 2026-11-12。実モデルは全呼び出しで `claude-sonnet-5-5`、欠落なし、費用は $2.36。1回目は [結果](negation-contrast-result.md)。

## 結論

- 計画の前提を満たした。target 群の24出力は、すべて書き換えられた（計画の基準は12以上）。1回目のように、原文のまま返された出力はなかった。
- 原文にない「ではなく」を作った出力は、36出力のうち0件（target 24、kept 6、no_negation 6）。計画の読み方では「起きていない」。
- 2文を1文にまとめた出力は、なかった。文の数が減った出力は0件。起きた書き換えは、冗長な言い回しの削除と、長い文や段落の分割だった。否定の文は、24出力のすべてで、句点で終わる独立した文として残った（各ケースの否定の文の末尾を、機械的に確かめた）。つまり、この測定でも、「2文を1文にまとめる」書き換え自体は起きていない。「起きていない」は、「書き換えは起きたが、その形の失敗は起きなかった」という意味である。
- この結果は、「この12本（102〜226字）の冗長な段落で、現行スキルが2文を1文にまとめて『ではなく』で結ぶ形の失敗を、起こさなかった」ことを示す。上流が測った約1,500字の下書きや、実文書での発生の有無は示さない。

補助の数のうち、no_negation 群で仲間を含む出力は0件。検出（`compare_rewrite.py` が作った箇所を示すか）は、作った出力が0件のため、この回では測れていない。1回目の事後の確認（人が書いた失敗例10本のうち1本だけ示す）が、検出についての唯一の数である。

### 読んだ内容（target 24出力を全件読んだ）

- 否定の文（u01 の「自動では書き換えません」、u02 の「サーバーの故障が原因ではありませんでした」など）は、全出力で、そのまま、または言い換えて残った。「ではありません」「ではない」の形は残ったが、「ではなく」の形はなかった。
- 否定の文とそのあとの文の間は、すべての出力で、別の文のままだった。段落の区切り（空行）を入れた出力は、ケースによって違う: u01・u03・u04・u08 は3回とも、u05・u07 は3回のうち2回、u02 は3回のうち1回、u06 は0回。u02（原因を述べる文が続く、対にしやすい形）は、3回とも、「ではありませんでした」の文と原因の文を、別の文のまま残した。
- u06 の1回は、「そのまま使い続けながら」を、独立した文「そのまま使い続ける。」に分けた。文の数は増えた。
- kept 群の「ではなく」は、6出力すべてで保たれた。
- 検出する対象になる出力がなかったため、`compare_rewrite.py` の検出の見落としは、この回では起きていない。

## 読むときの注意

- 下書きは、合成した12本の短い段落（102〜226字）で、実文書の頻度を表さない。上流は約1,500字の下書き12本で測っており、条件が違う。この結果で、上流の報告を否定も確認もしない。
- 冗長さは、書き換えを起こすために意図して入れた。実文書の冗長さとは違う。
- target の8本は、否定のあとの文が、否定を補う内容（「Aしない。Bする。」）で、対にしやすい形が中心だった。接続の弱い2文、または、否定と肯定の主語が違う2文は、少ない。計画の分類で、「ではなく」で結んでも「失敗ではない」とされる出力が多くなる設計だった可能性がある。この回は、作った出力が0件だったので、その影響は出ていない。
- 「失敗」の分類は、作った出力がなかったため、実際には使っていない。
- 3回の反復は独立した36種類の文章ではない。
- 計画の「検出」の限界（原文に否定があると、`markers` は新しい「ではなく」を示さない）は、1回目の事後の確認のとおり残る。この回で作った出力がなかったため、実際の見落としにはなっていない。

## この結果の使い方

- 引用するときは、「12本の冗長な段落（102〜226字）×3回では、原文にない『ではなく』を作った出力は0件」と、限定して書く。
- スキルの規則と `compare_rewrite.py` は、変えない。測らずに足さない。
- 1回目の事後の確認（原文に否定があると、`compare_rewrite.py` は新しい「ではなく」を `markers` で示さない）は、発生が確認できていないため、検出の型を足す根拠にしない。実文書で発生が見つかったときに、そのときの文を使って、別の Issue で扱う。
- 約1,500字の下書きなど、上流に近い条件での再測定は、この Issue の範囲に入れない。実文書や、その条件で「ではなく」の発生が見つかったときに、その文を使って、別の Issue で扱う。
