# 未使用文書による意味保持の追加評価

「どの文章でも失敗しない」ことを有限の検証で証明することはできない。この評価では、前の18ケースから分野・長さ・意味の関係を広げ、実際に確認した範囲を記録する。スキル本体は変更しない。

## 固定する範囲と合格条件

[未使用の自作16ケース](readability-generalization-cases.json)を、各3回、新しい文脈で1ケースずつ生成する。案内、社内精算、作業手順、障害報告、技術選定、依頼、研究メモ、データ取扱、引継ぎ、アンケート、設定説明、Markdown、長い運用ルール・調査報告・教材、資料からの報告作成を含む。実在の制度・調査・障害を引用した文章ではない。長い文書を含むが、書籍や複数ファイルにまたがる長文の評価ではない。

確認するのは、境界値、数値・単位、条件と例外、否定、比較や数量の範囲、主体、指示語、順序、完了・予定・未確定、観察と因果、伝聞、文の働き、コード・URL・引用など。読みやすさの勝敗は今回の合否に混ぜない。

生成前にスキル、入力、指示、設定を保存する。今回の入力・出力を見てスキルを調整した場合、その後の結果を未使用文書での確認とは呼ばない。追加の修正は回帰評価へ移し、新しい未使用文書を別に用意する。

優先順位は、現在のスキルを固定してこの集合を評価し、失敗・未判定を原文と照合し、必要ならその後に修正する順とする。今回の規模では、途中で失敗しなければ生成48回と採点4回の計52回のモデル呼び出しになる。実行時間と契約上の利用枠・料金を使うため、通常のローカルテストやCIからは呼ばない。人間による校正や実利用文書の収集は別の作業として残す。

事前の合格条件は次のすべてを満たすこと。

- 48出力が欠落なく得られ、すべて意味保持にpass。failまたはuncertainは合格に数えない。
- 採点の点検用12項目がすべて期待どおり。内訳は、境界値・条件・状態・主体・文の働き・数量・伝聞を意図的に変えた8項目と、正しい言い換え・分割・原文保持の4項目。
- 実モデル識別子が取得でき、生成・採点で一致している。失敗した呼び出しを成功例だけから除外していない。

通過した場合の表示は `PASS_ON_TEST_SET`、未達・欠落・不明は `HOLD`。点検用項目の正答は採点者へ渡さず、生成出力と混ぜて順序を入れ替える。この点検は人間による校正や、採点モデルの一般的な正確さの証明ではない。

## 実行

開発用の [evaluate_readability.py](../tools/evaluate_readability.py) は標準ライブラリだけで動く。配布スキルに外部モデルの必須依存を加えない。

```bash
# 準備のみ。外部通信やモデル呼び出しはしない。出力先は新規ディレクトリ。
python3 tools/evaluate_readability.py --out-dir /tmp/readability-plan

# 既存のClaude CLI・認証を使って生成と採点を実行する。
python3 tools/evaluate_readability.py --out-dir /tmp/readability-run --execute
```

Windowsなどでは、`/tmp/…`をその環境の一時フォルダ内の新しいパスに置き換える。`--suite PATH`で同じ形式の入力を指定できる。既存の出力先は上書きせず、再開・自動再試行もしない。CLIの導入や認証の変更をツールが代行することはない。

実行時は `sonnet / medium` と `--safe-mode --strict-mcp-config --tools "" --no-session-persistence` を指定する。スキルの3ファイルを明示して生成し、別の文脈で採点する。1ケースずつ生成するが、採点は最大15項目を一括処理する。採点には生成に用いたスキルや、点検項目の正答を渡さない。

出力先の `run.json` に入力・スキル本文・ハッシュ・生成採点指示・実出力・採点理由・実モデル・集計を保存する。`g001.json`などと`judge-1.json`などにはCLIの終了コード・生の標準出力・標準エラー・プロンプトのハッシュを保存する。途中で失敗しても、直前までの実出力と失敗記録を残す。

終了コードは、0=準備完了またはこの集合で合格、1=生成・採点完了だがHOLD、2=入力・呼び出し・採点形式などの実行失敗。準備だけの終了コード0を、評価の合格と解釈しない。

## 解釈の限界

自作の課題集合であり、日常の文章から無作為に抽出した標本ではない。3反復も独立した48種類の文章ではない。結果から一般的な失敗率や統計的な上限を計算しない。同じモデル系統の生成と採点には共通の見落としがありうる。異なるモデル、人間の校正、実際の利用文書・長い文書全体、製品のスキル起動、創作D・改行だけのCは別の確認として残る。

今回の実施結果は [追加評価の記録](readability-generalization-result.md) に残す。
