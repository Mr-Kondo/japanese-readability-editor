# 未使用例・回答反映・実際の報告文の確認結果

## 文脈

[Issue #216](https://github.com/Mr-Kondo/japanese-readability-editor/issues/216)の未確認事項を追加調査した。
前回の確認応答を短くする候補を変更せず、保存済みの現行版と候補版を比較した。
参考URLの修飾関係・比較対象の対応は着想元です。応答の短縮はそこからの派生仮説です。
前回の180文字条件による不採用判定は変更しない。v0.25.1とMacの導入先は維持する。

今回の範囲は、異なる文構造4件、説明・本文との併用2件、確認後の回答反映2件、利用者提供の分析報告文1件です。
各版で各ケースを3回生成した。確認後の2ケースには実際の初回応答と固定回答を履歴として渡した。
1版につき初回27件と後続6件、両版で66出力です。
履歴は単一プロンプト内のJSONで再提示した。製品の継続セッションや自動スキル起動の検査とは異なる。

## 核心的な論理

### 証拠

未使用例の応答全体の文字数は次のとおりです。単位は文字、各ケースは3出力の中央値です。
改行・注記・仮案を含む `len(text.strip())` を使った。

| 対象                         | 現行版 | 候補版 |
| ---------------------------- | -----: | -----: |
| 通知先と代理人の掛かり方     |    219 |    170 |
| 故障した物と交換した物       |    293 |    110 |
| 2人が調べた台数の範囲        |    348 |    119 |
| 全件か一部かという否定の範囲 |    334 |    142 |
| 対象12出力をまとめた中央値   |    317 |    121 |

中央値は約61.8%減り、4ケースすべてで小さくなった。
前回の比較型に近い質問の例だけでなく、異なる文構造でも短縮が起きる観測は得られた。
これは小規模な自作例での記述的な結果で、理解の速さや実利用価値の証明ではない。

一方、品質の確定判定は保留です。独立採点の点検10件×意味・課題の2軸、計20軸のうち1軸が期待と一致しなかった。
不一致は点検p03の課題軸です。理由は必要な確認の欠落を不合格としていたが、判定欄は合格だった。
実出力h01・候補1回目にも、判定欄と理由の食い違いを確認した。
全66出力と点検10件の入力・採点は保存できたが、事前条件に従い全体の合格率を確定しない。

### 仮説ごとの到達点

| 仮説                           | 確認できたこと                              | 残る限界                                   |
| ------------------------------ | ------------------------------------------- | ------------------------------------------ |
| 未使用構造でも短くなる         | 4構造すべてで中央値が減少                   | 全出力の品質条件は満たしたと扱えない       |
| 必要な説明を省かない           | 読み分けを求めた6出力は全て説明と質問を含む | 2出力の例文に条件の範囲の不揃いがある      |
| 既知情報の本文と質問を併用する | 本文は両版とも提示した                      | 候補2出力に指定外の追加質問がある          |
| 回答を反映して完成文を返す     | 後続12出力で主体・金額・未定を反映した      | 候補1出力に本文以外の作業説明がある        |
| 実際の報告文にも役立つ         | 実入力6出力を比較できた                     | 候補に断定の強まりがあり、優位性は示せない |

これらは保存出力の照合による観測で、点検条件を満たした総合的な合格率とは区別する。
利用者提供文の候補r01は、1・3回目とも原因の候補の列挙を確定形へ変えたと両採点者が判断した。
根拠は初回採点記録のj037（1回目）とj008（3回目）です。最終レビュワーには3回目の採点は未提示だった。
売上の伸びと売上高の水準の言い換えにも論点が残る。利用者への意図確認を依頼済みで、回答待ちです。採点後の確認として別記録で追跡する。
現行版にも、本文だけの指定に反して原文について解説した出力があった。
候補だけが問題を起こす、または今回の規則変更が問題の原因である、とは確定できない。

### 反論と採点監査

長さの短縮だけを理由に採用するのは不十分です。必要な内容・確実さ・出力形式も保つ必要がある。
また、独立採点は理由とラベルの整合、固定条件の適用にも揺れがあった。

初回の採点を保存したまま、不一致9項目を別のClaude Code呼び出しで監査した。
版名、点検の識別、固定期待値は渡さず、元の入力と両者の採点を提示した。
監査は方針をproceedとし、点検失敗と確定判定の保留を取り消さないことを確認した。
2件の判定欄と理由の不整合と、料金だけを尋ねる固定条件の緩和が確認された。
これらは元のラベルを上書きせず、監査の新しい記録へ分けて残した。

例文で箱にラベルがない条件を足す2出力については、監査は許容した。
主担当は、瓶だけに赤いラベル条件を掛ける読みより対象を狭めうると考え、解釈差を残した。
これは意味の事実断定と仮定例の違いとは別に、読み分けの説明として適切かという論点です。
原文にある料金の相違を未確認の料金から結論づける表現と、売上の言い換えも、初回の判定差を残す。
監査は探索的な追加記録で、解釈差の解決や事前条件の達成を保証しない。
複数の採点者の一致や監査を、正しさの保証にはしない。

## 重要ポイント

- 新しい事例でも短縮は観測した。「取り込める要素がない」と断定する根拠にはならない。
- 意味保持と課題達成の総合条件は確認できず、候補を採用する根拠は不足している。
- 確認への回答反映は模擬履歴で検査できたが、実際の継続セッションでの挙動は未確認。
- 利用者の実文は試せたが、クライアントの理解、満足度、報告の業務効果は測定していない。

## 平易な説明

わかりやすく言うと、質問を短くする効果は別の文章にも見られたが、文章の意味と依頼条件まで安定して守れるとはまだ確認できないということです。

## 自己批判と限界

生成と独立採点はいずれもclaude-sonnet-5-5で、同じモデルの好みに影響される可能性がある。
主担当は計画と版を知っているため盲検ではない。独立採点には版と主担当判定を隠した。
点検は課題failに偏り、完成本文の正常例の点検は少ない。
温度などCLIで固定できないサンプリング条件は不明です。
初回点検は19/20一致で条件未達です。監査で記入上の不整合を確認できても、事前条件の達成へ読み替えない。
未使用例は一人の主担当が用意した少数例です。別モデル、他の分野、長い会話、実際の自動起動は調べていない。

短縮を観測したという結論への信頼度は0.9です。これは主担当の主観的な確信で、統計的な確率ではない。
一般の文書での有用性やクライアントへの効果の信頼度は未評価です。
実利用効果の担当は利用者とCodex、確認時期は実際の読み手の評価が得られた時点、追跡先はIssue #216とする。

## 結論と検査

改善の可能性は残るが、保存済み候補をそのまま採用する根拠は得られなかった。
前回と同じく不採用を維持し、実行時ファイルと版は変更しない。
短縮効果と実文の失敗、採点の不整合を区別したことが、今回詰められた範囲です。

生成は66/66正常終了、実モデルはclaude-sonnet-5-5、effort medium、ツールなしです。
両版でCLI 2.1.332を使用した。前回の2.1.330とは異なるため、今回の両版内で比較し、数値を合算しない。
生成の経過時間は122.54秒です。最大3件の並行送信から回収までの実時間で、呼び出し時間の総和ではない。
生成費用はAPI換算5.7147137米ドル、独立採点7呼び出しは0.378488米ドルです。実際の追加請求額とは区別する。
計画レビュー2回は合計0.22917米ドル、採点監査は0.105788米ドルです。最終結果レビューは0.120434米ドルです。
段階3・4のレビューはclaude-sonnet-5-5、effort mediumでproceedだった。
点検ID・軸の明記、3回目の採点根拠、監査の限界、検査の実施者を補った。
全66件のハッシュなどの検査は主担当の実行記録に基づく。レビュワーが検査を独立実行したわけではない。
