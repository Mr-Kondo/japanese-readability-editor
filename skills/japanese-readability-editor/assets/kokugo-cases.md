# 国語の表記・用法の例

[kokugo-policy.md](../references/kokugo-policy.md) の判断が、実際の文章でどうなるかを示す。すべて説明用に作った例であり、実在の文書ではない。設定は `check_kokugo.py --profile` の値である。

各例の『直す』は修正例、『直さない』は変更してはいけない反例である。どちらも、同じ文章を設定ごとに検査して確かめている(`tests/test_kokugo_cases.py`)。

## 1. 公用文の送り仮名(`official` だけ error)

設定: `official`

```text
前: 申し込みを受け付ける。取り扱いの方法を示す。
後: 申込みを受け付ける。取扱いの方法を示す。
```

内閣訓令 別紙2(1)のただし書が、読み間違えるおそれのない複合の名詞を、送り仮名を省くものとする(`KOKUGO-OKURI-003`)。直後が『を』『の』なので、名詞と確定できる。

直さない:

- 設定が `general-tech` か `public-explanation` のとき。本則の形は誤りではなく、解説・広報等では送り仮名を省かずに書くことができる。
- 動詞。`official` でも「入り口で申し込む」の『申し込む』は本則どおりに書く。
- 直後が『、』などで動詞の連用形かもしれない箇所(「先に申し込み、支払う」)。確定した誤りにせず、要確認とする。

## 2. 許容形は誤りではない

設定: `general-tech`

```text
そのまま: 処理を行なう。結果を表わす。処理が終る。いなづまが光る。
```

『行なう』『表わす』は通則1の許容、『終る』は通則2の許容、『いなづま』は現代仮名遣い 第2 5(2)の許容である。誤りとして報告しない(`accepted_variant`)。

設定が `official` のときは、既定が本則なので推奨(`recommendation`)が出る。

```text
前: 処理を行なう。結果を表わす。
後: 処理を行う。結果を表す。
```

## 3. 外来語の長音符号(設定で区分が変わる)

```text
サーバを再起動する。
```

| 設定 | 区分 | 理由 |
|---|---|---|
| `general-tech` | `accepted_variant` | 告示が、慣用に応じて長音符号を省くことを認める(留意事項その2 Ⅲ 3 注3) |
| `public-explanation` | `recommendation` | 考え方が、長音符号を用いて書くのが原則とする(解説 Ⅰ-3エ) |
| `official` | `recommendation` | 同上 |

組織の用語集が『サーバ』を指定している場合は、`use: サーバ` を渡す。`official` の推奨と食い違うので、黙って片方を適用せず、`needs_context` として食い違いを示す。

## 4. 副詞・接続詞の漢字と仮名(`official` だけ推奨)

設定: `official`

```text
前: すべての設定とログを確認し、AおよびBを記録する。且つ、安定させる。
後: 全ての設定とログを確認し、A及びBを記録する。かつ、安定させる。
```

副詞は原則として漢字(『すべて』→『全て』)、接続詞は原則として仮名(『且つ』→『かつ』)で書く(内閣訓令 別紙1(2)イ・オ)。ただし『及び』『並びに』『又は』『若しくは』の4語だけは漢字で書く(『および』→『及び』)。

直さない:

- `public-explanation`。解説・広報等では、『すべて』『および』と仮名で書いてよい(考え方 本文 Ⅰ-1 ただし書)。
- 『かなり』『ふと』『やはり』『よほど』。仮名で書く語である。
- 『きわめて』『はじめて』『さらに』『もっとも』。動詞の連用形や接続詞の可能性があるので、確定した指摘にせず要確認とする。

## 5. 現代仮名遣いの明確な誤り(どの設定でも error)

```text
前: こんにちわ、田中です。そうゆう場合は再実行する。
後: こんにちは、田中です。そういう場合は再実行する。
```

助詞の『は』は『は』と書き(第2 2)、動詞の『いう(言)』は『いう』と書く(第2 4)。

直さない:

- 引用(ブロッククォート)の中の『こんにちわ』。引用は保護対象である。
- コードブロックの中の文字列。

## 6. 『づつ』は例示から断定しない

```text
少しづつ進める。
```

告示が許容を示すのは『ひとりずつ』を含む例示までである。『少しづつ』への適用は、例示から断定せず、要確認とする(`KOKUGO-KANA-005`)。『ひとりづつ』は許容形として扱い、直さない。

## 7. 表外漢字は要確認(固有名詞は触らない)

設定: `public-explanation` か `official`

```text
前: 地域の絆を深める。
後: 地域のきずなを深める。（または 絆（きずな）に振り仮名を付ける）
```

表外漢字は、原則として用いない。言い換える、仮名で書く、振り仮名を付ける、のどれを選ぶかは、読み手による。

直さない:

- 固有名詞(人名・地名・組織名)。『髙橋』のような表外漢字を、常用漢字に置き換えない。`--glossary` の `protect:` に書いて除外する。
- `general-tech`。常用漢字表は専門分野や個々人の表記には及ばない(前書き2)。

## 8. 異字同訓は要確認にとどめる

設定: `public-explanation` か `official`

```text
時間を計る。
```

『はかる』は、図る・計る・測る・量る・謀る・諮るの使い分け例がある。語義(時間や数を数えるのか、長さを調べるのか)で決まる。読みだけでは決まらず、使い分け例は「一つの参考」である。この skill は正しい漢字の候補を示さず、要確認として示すだけである。

## 9. 重ね言葉は、慣用のものを直さない

設定: `public-explanation` か `official`

```text
前: 約20名くらいが参加した。
後: 約20名が参加した。
```

直さない:

- 『まず最初に』『従来から』『返事を返す』『排気ガス』『被害を被る』。考え方が、慣用や強調として一概に誤りとも言えないとする例である。

## 10. 『か所』『か月』

設定: `public-explanation` か `official`

```text
前: 3ヶ所を直す。7カ月かかる。
後: 3か所を直す。7か月かかる。
```

直さない:

- `general-tech` の『3ヶ月』。
- 概数の『数箇所』『何箇月』。考え方が、概数や漢数字では『箇』を用いるとする。

## 11. 保護対象は触らない

次は、規則に当てはまる表記があっても適用しない(`excluded`)。

- YAML frontmatter。
- fenced code block とインラインコード。
- URL とリンク先(日本語のパスを含む)。
- ブロッククォート(引用)。
- HTML コメントと HTML タグ。
- `<!-- kokugo-ignore-start -->` から `<!-- kokugo-ignore-end -->` まで。
- 用語集の `protect:` に書いた語。

## 12. 表記を直すときも、意味を保存する

国語の規則を理由に、数値、単位、条件、例外、否定、主体、断定の強さを変えない。

```text
元: 申し込みは3か所に限る。ただし、例外は認めない。
正: 申込みは3か所に限る。ただし、例外は認めない。
誤: 申込みは3か所に限らない。ただし、例外を認める。
```

『誤』は、表記の修正に見えて、条件の範囲、否定、断定を変えている。モード B では、直した後に `compare_rewrite.py` で数値・条件・否定の増減を確認する。

## 13. モード C は本文を変えない

モード C では、国語の規則を理由に、文言・句読点・語順を変更しない。表記上の問題を見つけても、本文は変えず、報告するだけにとどめる。

```text
前: 申し込みを受け付ける。サーバを再起動する。
後: 申し込みを受け付ける。

サーバを再起動する。
```

挿入したのは改行と空行だけである。『申し込み』も『サーバ』も、直さない。確認には、空白やタブの置換・削除も見つける `--strict` を使う。

```bash
python3 scripts/verify_preservation.py --strict before.md after.md
```

既定の `verify_preservation.py` は、空白全般を無視する。文と文のあいだの空白を消しても合格するので、「改行と空行の挿入のみ」の確認には足りない。
