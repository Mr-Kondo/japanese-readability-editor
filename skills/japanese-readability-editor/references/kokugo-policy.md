# 国語の表記・用法の適用方針

文化庁の資料に基づく表記・用法の判断を、どの文書に、どの強さで当てるかを決める。モード A・B・C・D とは独立した設定として扱う。規則の一覧は [kokugo-notation.md](kokugo-notation.md)、出典は [kokugo-sources.md](kokugo-sources.md) にある。

## 1. 資料の性格を区別する

文化庁の資料は、すべてが同じ強さの規則ではない。すべてを一律の正誤判定として扱わない。

| 性格 | 資料の例 | この skill での扱い |
|---|---|---|
| 内閣告示 | 常用漢字表、現代仮名遣い、送り仮名の付け方、外来語の表記、ローマ字のつづり方 | 一般の社会生活における目安・よりどころ。専門分野や個々人の表記には及ばない(各告示の前書き)。明確な条件を満たす場合に限り error の根拠にできる |
| 内閣訓令 | 公用文における漢字使用等について | 各行政機関が作成する公用文が対象。`official` でだけ強く扱う。固有名詞は対象外、専門用語・特殊用語では従わなくてよい |
| 建議・報告・答申 | 公用文作成の考え方、「異字同訓」の漢字の使い分け例、敬語の指針 | 手引・参考。recommendation か needs_context まで。error の根拠にしない |
| この skill の運用判断 | 区分の割り当て、品詞が決まらない語を要確認に下げる判断、混在の確認、文の長さの目安 | 公式資料の規定とは区別する(規則データの `provenance` と `skill_decisions`) |

「公用文作成の考え方」自身が、文書の目的や種類に応じて書き表し方を変える余地を認めている。法令に準ずる告示・通知等は公用文表記の原則に従い、記録・公開資料等は原則に基づきつつ読み手に合わせて工夫し、広く一般に向けた解説・広報等は読みやすさを優先して書き表し方を工夫する(本文 基本的な考え方 1(2))。適用設定は、この区別に対応させた。

## 2. 適用設定

| 設定 | 用途 | 動作 |
|---|---|---|
| `general-tech`(既定) | 技術・業務文書 | 明確な誤りを確認し、専門用語・組織の表記・許容形を尊重する。公用文の細則は要求しない |
| `public-explanation` | 一般向けの解説・案内・広報 | 読み手に応じた表記を検討する。説明不足は、原文に根拠がなければ指摘にとどめる |
| `official` | 公用文基準が明示された文書 | 公用文固有の表記・用語の運用も確認する |

- 利用者が指定しなければ `general-tech` とする。文体が堅いという理由だけで `official` にしない。
- `official` は、公用文の基準に従うことが依頼や文書の中で示されているときに選ぶ。
- `public-explanation` では、原文にない情報を足さない。説明が足りないと思っても、原文に根拠がなければ指摘にとどめ、利用者に素材を求める。
- 設定は `check_kokugo.py --profile` で渡す。モードの指定(A・B・C・D)とは別に決める。

## 3. 判定区分

| 区分 | 意味 | 扱い |
|---|---|---|
| `error` | 適用条件と修正根拠が明確な誤り | 修正する。モード C では修正せず報告する |
| `recommendation` | 選択した基準では推奨されるが、一般的な誤りとは限らない | 文脈と読み手を見て判断する。直さなくてよい場合がある |
| `accepted_variant` | 許容される表記 | 誤りとして報告しない。直さない |
| `needs_context` | 意味・品詞・文脈の確認が必要 | 文脈を読んで決める。確定した誤りとして扱わない |
| `excluded` | 保護対象など、適用しない箇所 | 触らない |

- 許容形や適用範囲外の表記を、誤りとして報告しない。
- 常用漢字の字種だけを確認して、音訓まで確認済みとしない。
- 異字同訓を、読みだけで決めない。国語に関する世論調査の多数派・少数派だけで、正誤を決めない。
- 検査が見つけられなかったことは、規則に違反していないことを意味しない。規則に登録した語・表記だけを検査している。

## 4. 組織の用語集・表記指定

組織の用語集や表記指定が示されたら、先に確認する。

- 固有名詞・専門用語は、`--glossary` の `protect:` に書く。規則を適用しない(`excluded`)。固有名詞・専門用語を自動では識別できないので、人が指定する。
- 組織が表記を指定しているときは `use:` に書く。適用設定の推奨と食い違う場合は、黙って片方を適用せず、`needs_context` として食い違いを示す。どちらに従うかは利用者に確かめる。
- 公用文への準拠指定と組織の用語集が競合するとき(例: 用語集は『サーバ』、公用文の手引は『サーバー』)も同じである。競合を示し、決めない。

## 5. 表記をどれに合わせるか

次の順で決める。「文書の中で多数派の表記に合わせる」ことでは決めない。

1. 明示された表記基準と、組織の用語集を確認する。
2. 指定がなければ、適用設定に従う。
3. 複数の表記が許容される場合にだけ、文書内の統一を判断材料にする。
4. 多数派であることを理由に、明確な誤りを広げない。

許容される表記の混在は `KOKUGO-CONSIST-001` が示す。これは、この skill の運用判断であり、公式資料がすべての許容形の混在を禁じているわけではない。回数の多い表記は、候補に添えるだけである。

## 6. モード A・B・C・D との関係

| モード | 国語の規則の扱い |
|---|---|
| A. 新規生成 | 構成と論理を先に設計する。書いた後に、適用設定に従って確認する |
| B. Rewrite | 構成・論理・読みやすさを確認した後で、国語の表記を確認する。意味を保つ範囲で直し、直したら `compare_rewrite.py` で意味の変化候補を確認する |
| C. Paragraph-only | **国語の規則を理由に、文言・句読点・語順を変更しない。** 改行と空行の挿入だけを行う。表記上の問題を見つけても、本文は変えず、報告するだけにとどめる |
| D. 小説モード | 作品の設定・文体と [fiction-writing.md](fiction-writing.md) を優先し、適用範囲を確認する。口語・創作表現を公用文へ正規化しない。既存の検査 CLI と既定値は変えない |

A/B では表記の修正より先に、構成と論理を確認する。数値、単位、条件、例外、否定、主体、因果関係、断定の強さは、表記を直すときにも保存する。固有名詞、専門用語、API 名、コード、コマンド、URL、引用、出典は保護する。

## 7. 文の長さの目安の位置づけ

この skill の「段落は200字以上を候補」「1文は30〜45字を目安に、46字以上を候補」「20字未満の文が3文以上続く箇所」は、修正候補を見つけるための、この skill の運用上の目安である。文化庁の基準ではない。合否の基準にもしない。

文化庁の「公用文作成の考え方」の解説は、一文の長さについて「適当な長さは一概に決められないが、50〜60字ほどになってきたら読みにくくなっていないか意識するとよい」と述べるにとどまる(解説 Ⅲ-3ア、PDF p.44)。基準値としては示していない。

## 8. 機械検査でできること、できないこと

`check_kokugo.py` は、規則に登録した語・表記を、保護対象を除いて機械的に探す。

- できる: 登録した語の表記の検出、位置の特定、適用設定ごとの区分、出典の提示、同じ入力からの同じ出力。
- できない: 品詞や用法を文脈から決めること(形態素解析を使わない)、固有名詞・専門用語の識別、意味の保存の保証、敬語・ローマ字・字体の適否、構成や論理の適否。
- 登録していない語・表記は、検査していない。出力の `coverage` に、検査したものと、していないものを示す。

意味の保存に関する検査(`compare_rewrite.py`、`verify_preservation.py`)も、用意したケースでの機械的な確認であり、すべての自然言語入力に対する保証ではない。
