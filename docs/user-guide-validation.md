## Claude Codeの繰り返し試験とガイドの修正

同じ条件で、例9と例12をそれぞれ3回実行しました。その後、依頼文だけを補い、各3回を再実行しました。Skill本体、モデル、権限の設定は変えていません。

| 例 | 元の依頼文、3回 | 補った依頼文、3回 |
|---|---|---|
| 9：小説の続き | 空白・改行を除いて218、210、183字。1回が200字未満 | 「空白・改行を除いて数え、200〜300字に収まることを確認」を追加。215、219、215字で、3回とも範囲内 |
| 12：用語集付きの推敲 | 1回は完了したと報告。2回は一括Bashの拒否があり、照合・再検査などが未完了 | 編集ツールを使い、退避・表記検査・編集・照合・再検査・後片付けを分けるよう指定。3回とも拒否記録なし。保存先を独立に再読して修正を確認 |

元の一括Bashには、ファイルの上書き、検査、一時ディレクトリの削除が含まれていました。初回の返答は拒否理由を「元に戻せない上書きや削除」と説明しています。構造化された拒否記録だけでは、どの操作が主因かは確定できません。

例4にも編集・照合・後片付けを分ける指示を加え、1回再実行しました。拒否記録はなく、保存された本文が「ログ出力を確認できる。保存期間は30日である。」になったことを再読しました。

表の例12の3回では、保存結果と拒否記録は独立に確認しています。照合・再検査・後片付けの完了は、CLIの最終報告による確認です。少数回の成功から、今後の出力や権限判断の成功率は推定できません。

さらに例12を1回、ツールの実行履歴を含む形式で確認しました。退避、編集前の表記検査、`Edit`、照合、再検査、今回作った退避ファイルと空のディレクトリの削除を、別々の呼び出しで確認できました。検査結果と保存先も再読しました。この追加試験も拒否記録はなく、履歴の抜粋を検証データに含めています。

後片付けの呼び出しは、削除後の `ls` が「存在しない」と返したため終了コード1でした。退避先が残っていないことは独立に確認しました。また、照合の実出力は「原文の1文に対応する書換えなし」でした。モデルの最終報告はこれを「書換えた文の対応なし」と説明しており、検査結果の説明まで完全に正確だったわけではありません。
