# デジタル庁の業務文書による評価データ（P0）

Issue #40。共通の方針は[公開文書による評価データ整備の計画](public-document-evaluation.md)に従います。ここでは文書群に固有の選び方と保持条件を定めます。

## 状態

本文は未収集で、効果は未測定です。台帳 `evals/public-documents/manifest.json` には、対象の出典5件を `planned` で登録しただけです。取得日・版・原ファイルのハッシュ・利用条件の確認日は、すべて未記入です。

## 目的

推敲で、作業主体、実施条件、完了条件、必須／推奨の強さを変えないかを調べます。

出典ページは <https://www.digital.go.jp/resources/standard_guidelines> です。文書名の正式表記、版、公開日は取得時に確認して台帳へ記録します。

## 抜粋の選び方

- 手順、役割、要件のいずれかを、その抜粋だけで読める文章を選ぶ。前後の章や表を読まないと主体や条件が分からない抜粋は除外し、理由を記録する。
- 標準テンプレートの未記入欄・記入例を、実案件で確定した情報として補わない。テンプレートの抜粋は「テンプレートが何を求めているか」の文章に限る。
- 変更不要の対照例を含める。例えば、すでに主体・条件・完了条件が一文ずつ明確な文。
- 同じ文書の別章を複数選んでも、独立した原本として数えない。5件の出典から10抜粋を選べば、独立した原本は最大5つ。

## 取得と照合

1. 利用できるWord等の編集可能な形式を優先し、PDFは代替とする。取得した原ファイルの SHA-256 を `raw_sha256` に記録する。
2. 抽出した見出し・段落・箇条書き・表・脚注参照を原本と見比べ、`correspondence`（確認者・確認日）を記録する。表や図に依存して文意が変わる抜粋は除外する。
3. 変換は `transform_history` に一段ずつ残す。

## 利用条件の確認

Issue は原則として公共データ利用規約（PDL1.0）の適用を前提にしています。次は取得時に個別に確認し、確認日と URL を `license` に記録します。

- 利用規約の URL: <https://www.digital.go.jp/copyright-policy>、<https://www.digital.go.jp/resources/open_data/public_data_license_v1.0>
- 採用する文書自体に、個別の条件がないか。
- 第三者の引用、図、写真、表が含まれていないか。含む場合は、その部分を含まない抜粋だけを採用する（`third_party_content: none`）。
- 書誌情報（題名・版・日付）の条件が、本文と同じか。

表示は、出典と加工主体を書き、推敲文を政府の公式文書として提示しないことを `attribution` と `modification_notice` へ残します。文面の例（正確な表記は取得時に利用規約で確認する）:

> 出典: デジタル庁「〈文書名〉」（〈URL〉）を、〈加工主体〉が抜粋・加工した。デジタル庁が作成・確認した文書ではない。

規約の確認が済むまで、本文を台帳へ入れません（検証ツールが拒否します）。

## 保持要件

`preserve` の `kind` に、次の対応で記録します。いずれも抜粋内の引用（`quote`）と、人の確認者・理由が必要です。

| 保持するもの | `kind` | 補足 |
|---|---|---|
| 順守内容（Normative）／参考内容（Informative） | `strength` | 項目の `strength` に `normative` または `informative` を書く。判断の根拠文を `quote` にする |
| 誰が行うか | `actor` | 主体の追加・欠落・入れ替えを不具合として扱う |
| 期限・時期 | `deadline` | |
| 前提・実施条件 | `condition` | |
| 例外 | `exception` | |
| 成果物・完了条件 | `deliverable` | |
| 主張・数値 | `claim`、`number` | |

`allowed_changes` には、許容する変更（文の分割、語順、接続表現の整理等）を書きます。専門用語の和語化と、参考情報を義務に変える変更は、許容に入れず不具合として評価します。

## 評価の設定

- モードBを明示し、対象読者は生成前に決めて `audience` に書く。`request` も固定する。
- 比較・統計用の `document_id` は台帳の `source_id`、理解問題用は抜粋IDにする（[接続の制約](public-document-evaluation.md#既存ツールとの接続)）。
- 行政文書群として独立に集計する。他の文書群や青空文庫と合算しない。
- 理解問題は「誰が」「どの条件で」「何を完了すべきか」を問い、根拠を抜粋内の引用にする。出題・選択肢・正解・根拠・確認者・理由を人が原文と照合する。
- 組織の責任分担が実務として適切かは評価しない。文書に書かれた責任が保たれているかだけを見る。
