## 目的

自然な文章で、論旨・比喩・反復・対比・否定を壊さず、変更不要と判断できるかを評価します。文学作品を、現代の技術・業務文書の代表にはしません。

## 取得で分かったこと

- XHTML 版は Shift_JIS です。`tools/extract_html_text.py` が `meta` の文字コード宣言から判別します。本文の範囲は `div.main_text` です。
- ルビは `親字《ルビ》` の形で残します。外字は画像の代替文字を本文として残します（例: 牧野の「足摺岬（蹉※(「足へん＋它」、第3水準1-92-33)《さだ》の岬）」）。傍点は `［＃傍点］…［＃傍点終わり］` の形で残します。この三つは削除せず、保持要件の `notation` で保護します。
- 外字の代替表記は、テキスト版（`※［＃…］` の形）と書式が異なります。`azmk-collect` の機械照合が一致しないのは、この違いによります。
- 底本の誤記や、著者の時代の語彙・事実は直しません。例えば中谷宇吉郎『科学は役に立つか』は、湯川さんの月給を「多分百三十三円」と推量し、研究費を、ある段落では「年に二百円とか三百円」、次の段落では「年間の研究費百円」と書きます。この揺れを直さず、保持要件に記録しました。
- 小説の構想・続きや、旧字旧仮名の現代語化は依頼に含めません。

選定基準は台帳の `groups.aozora-essays.selection` に記録しています。選び方は、書架情報で新字新仮名・著作権なしの作品を絞り、各作品を段落単位で抽出して、トピックが重ならないよう選ぶ方法でした。走査した全段落は記録していません。**手作業の選定であり、無作為抽出ではありません。**

分割は**著者単位**です（`lineage_id` を著者ごとに付け、検証ツールが同じ系列の抜粋を同じ側に置くことを確認します）。モデル出力の生成・閲覧の前に決め、台帳に日付付きで記録しました。限界は次のとおりです。

- 著者数は調整用2、最終評価用2で、作品数は5です。**作品の複数抜粋は、独立した作品数として数えません。**
- 寺田寅彦と中谷宇吉郎は師弟で、文体や発想が近い箇所があります。両側に分かれても独立とは言えません。
- 随筆だけで、説明文や講演は含みません。集計の信頼区間は意味を持たず、記述的な予備評価にとどまります。
- 変更不要の対照例は `azml-necessary` です（評価前に私が判断したもので、人の確認が必要）。

## 保持要件

`kind` の対応は、[Python の文書群](public-documents-python.md#保持要件)の表に加えて、次のとおりです。

| 保持するもの | `kind` | 補足 |
|---|---|---|
| 主張・見解 | `claim` | 「あまり」「ようだ」「ではなかろうか」など、控えめな言い方を断定にしない |
| 対比・譲歩 | `contrast` | 「たとえ楽しかったとはいえ…努力した」のように、両立する二つを一つに整理しない |
| 否定 | `negation` | 「〜ではない」「〜わけではない」を落とさない |
| 論理関係・理由 | `logic` | 「必要条件」と「充分なる条件」、原因の推量 |
| 比喩・反復・意図的な曖昧さ | `figure` | 旅人、富士、卵とひび。「永生きじゃった――永生きじゃった――」の反復を整理しない |
| ルビ・外字・傍点の記法 | `notation` | `《ルビ》`、外字の代替表記を削らない |
| 数値・固有名・時点 | `number`、`claim` | 金額、年、「現在は知らないが」のような時点の限定 |

`allowed_changes` には、許容する変更を書きます。草案では全項目に「文の分割・結合、語順や接続表現の整理（主張・対比・否定・論理関係・数値・固有名・意図的な反復や比喩を変えない範囲。旧字や旧仮名への変更、現代語化、科学内容の更新は含めない）」としました。**歴史的語彙や著者の評価を、現在の事実で直したり、科学内容を更新したりする変更は許容せず、不具合として評価します。**

## 評価の設定

- モードBを明示し、現代語化や科学内容の更新は依頼に含めない。対象読者は生成前に決めて `audience` に書く。**対象読者・依頼は未決定。**
- 比較・統計用の `document_id` は台帳の `source_id`（作品）、理解問題用は抜粋IDにする（[接続の制約](public-document-evaluation.md#既存ツールとの接続)）。
- 随筆の補助群として独立に集計する。業務・技術文書や行政文書の結果と合算しない。
- 理解問題は、抜粋だけから答えられる形にし、人手で原文と照合する。
- 原文をそのまま返すことを失敗扱いにしない。

## 人が行うこと

1. 各 `candidate` について、台帳の本文を原本（図書カードの XHTML）と見比べ、`correspondence` に確認者・確認日を記入する。外字・ルビ・傍点の扱いを見る。
2. 著者の没年、保護期間、底本の扱いを確認し、`third_party_content` を確定する。
3. `preserve` の各項目と `questions` を原文と照合し、`confirmed_by`・`reason`、`verified_by`・`verification_reason` を記入する。修正や削除をしてよい。
4. `azml-necessary` を変更不要の対照例にしてよいか判断し、`no_change_reason` を確定する。
5. 採用するものの `status` を `adopted` に変える。`--readiness` の出力が空になるまで繰り返す。
6. 対象読者・依頼を決め、`cases` JSON を作って[計画の手順](public-document-evaluation.md#手順)に進む。
