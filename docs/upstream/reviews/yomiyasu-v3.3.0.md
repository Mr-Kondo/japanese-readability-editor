## 現状の実測

現行の `compare_rewrite.py` を regex 解析で人工8組に実行した。保証の追加、主体変更、例外の拡大、対象の変更、入れ子の相手の逆転では候補が出なかった。再発防止策を保証に変えた組では否定表現の増加を示した。各実行は約0.047〜0.054秒、終了コードはすべて0だった。

この結果は、指摘がないことを意味保持の証拠にできないと示す。比較スクリプトは今回変更しない。

## 外部レビューと限界

計画を Codex（gpt-5.6-sol）と Claude Code（claude-sonnet-5-5）で確認した。保証を保つ同義例の不足と、評価例の不自然さを指摘され、修正した。Claude Code の再レビューで計画を承認された。Antigravity は出力を得られず終了したため、レビュー済みとは扱わない。

評価用は規則の例と分けた人工12組であり、語順の変更など意味を保つ例も含む。Claude Code（claude-sonnet-5-5）で新旧の規則を同じ12組に各2回適用し、いずれも12組すべてを正しく判定した。同文の1組は誤警報の評価に数えない。

この結果で確認できたのは、規則との整合性だけです。改善は観測していません。実際の推敲品質や実利用の改善率は未確認です。構造・条件の自動判定を実装したとは主張しない。実装後の確認結果は #214 と PR に残す。
