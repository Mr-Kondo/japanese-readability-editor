# yomiyasu v3.1.0 の確認記録

- 参考先: [nanaism/yomiyasu](https://github.com/nanaism/yomiyasu)（MIT）
- 範囲: 基準 `v3.0.1`（`b9a69a3`）から `v3.1.0`（先頭 `db78b9b`）まで
- 追跡 Issue: #197
- 確認日: 2026-11-16

## 読んだ範囲

`python3 tools/upstream_watch.py check --only yomiyasu` の結果、v3.1.0 の CHANGELOG、監視対象7ファイルの差分を読みました。上流のスクリプトは実行していません。

## 変更の要約

- 推敲の規則と出力は、版番号を除いて v3.0.1 から変更なし
- Skill 内の `.codex-plugin/plugin.json` を削除し、コピー型の配置で Skill 名がプラグイン名付きにならない構成へ変更
- Python ソースに直接書いていた U+FEFF を `\ufeff` へ変更（不可視文字を除去する外部ツールによる BOM 処理の変化を防止）
- CI の分割とパッケージ検査を追加し、配布する規則は変更なし

## こちらとの照合

2026-11-16 に `skills/japanese-readability-editor/` 配下の33ファイルを UTF-8 として走査しました。

| 項目                                         |       実測 | 判断                                                                                     |
| -------------------------------------------- | ---------: | ---------------------------------------------------------------------------------------- |
| Skill 内の `.codex-plugin`・`.claude-plugin` |  0ファイル | 既に上流 v3.1.0 と同じ方向です。追加対応は不要です                                       |
| U+FEFF、ゼロ幅文字、双方向の制御文字の直書き |        1件 | `scripts/kokugo_engine.py` の `parse_glossary` に同型の問題があります。#200 で追跡します |
| 配布する Skill のファイル                    | 33ファイル | 検査範囲を固定するために数えました。外部ツールの全挙動を保証する値ではありません         |

U+FEFF を除去したソースをメモリ上で読み、BOM 付きの用語集を比較しました。現行では `use: サーバ` を指定表記として読みます。U+FEFF の直書きだけを除去すると、同じ行を BOM 付きの保護語として読み、分類が変わりました。BOM 付きコメントもコメントとして除外されなくなりました。

## 採否

| 項目                                   | 採否             | 理由・行き先                                                         |
| -------------------------------------- | ---------------- | -------------------------------------------------------------------- |
| Skill 内のプラグイン設定を置かない構成 | 変更なし         | 既に同じ構成です                                                     |
| U+FEFF を可視なエスケープ表記へ変える  | 評価してから採る | 解釈差を再現しました。実装、回帰テスト、配布物検査は #200 で扱います |
| 上流のパッケージ管理・CI 構成          | 採らない         | こちらの配布経路と CI は別の構成です。上流の実装を移植しません       |
