## こちらとの照合（実測を含む）

- `compare_rewrite.py` の速度: 合成文書で 4.3 万字 9.1 秒、21 万字 235.7 秒（約 5 倍の長さで約 26 倍の時間）。→ #52
- Windows（cp932）の出力: `PYTHONUTF8=0 PYTHONIOENCODING=cp932` で、絵文字を含む変更文を引用する出力が `UnicodeEncodeError` になることを再現した。標準入力と `--json` は問題なし。→ #53
- `gh skill`（gh 2.102.0）: リポジトリ名だけでは `no skills found`。`skills/japanese-readability-editor/SKILL.md` のパス指定では見つかる。→ #54
- 文の種類: こちらは「文の働きと時制が同じか」を持つが、例え・皮肉と反語がなく、書き直す前に控える手順がない。`markers` に伝聞・例え・意見の独立した印がない。→ #55
- AI の名残: 指示の名残、仮置き、チャット応答の名残は、こちらに該当する指示がない。→ #56
- 見出し: 上流は警告を見出しから本文へ移す。こちらは「結論や警告を伝える見出しは薄めない」。逆の向きなので採らない。→ #57

## 外部の意見の反映

Codex（gpt-5.6-sol）と Antigravity に、Issue の草稿を読み取り専用で見てもらい、次を反映した。

- #52 の「2 乗以上」を「2 乗に近い」に直し、測定を 4 点・各 3 回以上にする完了条件を足した。
- #53 の「何もしない」と「すべての CLI で失敗しない」の食い違いを直し、cp932 の端末で文字化けしうることを書いた。
- #55 の機械の印は、既存の印を変えずに追加だけにし、先に手順と例を行う順にした。
- #56 は 3 項目に絞り、「もちろん」「大げさな名詞」「擬人化」「これにより」と、書式の直しは #57 に回した。
- #57 の「会話の事実で埋める」「名前だけの呼び出し」は、当面見送りにした。
- #58 に、上流の文章を未信頼の入力として扱う節を足し、自動化の既定を「PR の作成まで」にし、`skills/`・`tools/`・`.github/` は自動でマージしないことにした。

## 限界

- 上流の測定は作者の手元の小規模なもので、改善率を示す数字ではない。上流の主張は仮説として扱った。
- 実測は合成文書と macOS 上の環境変数による再現で、実文書の分布や実機の Windows を反映しない。
- 外部の意見は、草稿だけを読んだもので、上流の実装を実行して確かめたものではない。
