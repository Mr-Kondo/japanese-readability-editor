## 目的

運用手順の推敲で、安全上の制約、既定値、前提、推奨と保証の区別、警告と例外を落とさないかを調べます。実クラスタでの運用安全性や設定の動作は、文章の比較だけでは保証せず、評価しません。クラスタも構築しません。

## 対象

出典は <https://kubernetes.io/ja/docs/> の4ページです。

| 台帳ID | ページ | 分割 |
|---|---|---|
| `k8s-pod-lifecycle` | Podのライフサイクル | 調整用 |
| `k8s-probes-task` | Liveness Probe、Readiness ProbeおよびStartup Probeを使用する | 調整用 |
| `k8s-secret` | Secret | 最終評価用 |
| `k8s-resources` | コンテナのリソース管理 | 最終評価用 |

サイトの版表示は v1.37 です（2026-10-17 取得）。**日本語の本文は英語版より古く、機能状態の注記も古い版のまま残ります。** たとえば Secret の Immutable は「Beta since v1.19」、ローカルのエフェメラルストレージは「Beta since v1.10」、Pod のライフサイクルの本文の最終更新は 2024-02 です。これらの注記は技術内容の更新をせず、保持対象として扱います。各ページの原本コミット（`kubernetes/website` の `content/ja/docs/…`）は台帳の `version` と `attributes.source_commit` に記録しています。

## 取得で分かったこと

- Hugo の出力は終了タグを省略しています（`</p>` や `</li>` が無い）。抽出器 `tools/extract_html_text.py` は、省略された終了タグを開始タグで補って段落に分けます。本文の範囲は `div.td-content` です。
- 表（Secret の組み込み型の表、Pod のフェーズの表）は、行・列の位置が抽出で失われ、一部は英語の説明が残ります。表の抜粋は採らず、除外として記録しました。
- 注意・備考のボックスは、見出し（`注意:`、`備考:`）と本文が別の段落として出ます。保持対象は、見出しではなく本文の記述（警告、前提）です。
- 「FEATURE STATE: Beta since Kubernetes v1.19」の行は、本文として抽出されます。バージョン注記は `kind: version` で保持します。
- 用語集ツールチップなどのショートコードは、Markdown ソースからは表示名を復元できないため、機械照合で不一致になることがあります。

## 抜粋の選び方と分割

選定基準は台帳の `groups.kubernetes-docs-ja.selection` に記録しています。その抜粋だけで、手順・制約・既定値・前提・警告のいずれかが読めるものを選びました。選び方は、各ページを段落単位で抽出し、「してはいけません」「すべきです」「必要があります」「デフォルト」「可能性があります」等を含む段落を走査して、トピックが重ならないよう選ぶ方法でした。走査した全段落は記録していません。**手作業の選定であり、無作為抽出ではありません。**

| 側 | 出典 | 抜粋 | 主な内容 |
|---|---|---|---|
| 調整用 | Podのライフサイクル、Probe の手順 | 10件 | 再起動ポリシーと数値、Probe の方式と既定値、強制削除の注意、Readiness の条件 |
| 最終評価用 | Secret、コンテナのリソース管理 | 15件 | 暗号化されない保存、作成順序と1MiB、Immutable の版、requests と limits、拡張リソースの整数制約 |

分割はモデル出力の生成・閲覧の前に決め、台帳に日付付きで記録しました。限界は次のとおりです。

- トピックと分割が交絡します。Probe に関する記述は調整用側に集めました。
- 全て kubernetes.io の日本語版で、翻訳者・系列の偏りは抑えられていません。独立した原本は調整用2、最終評価用2です。
- 最終評価用の候補15件は、Secret（9件）とコンテナのリソース管理（6件）の2ページに由来します。1ページあたりの抜粋数は集計に反映せず、原本単位で扱います。
- 変更不要の対照例は `kpl-single-schedule` と `ks-tls-protected` です（評価前に私が判断したもので、人の確認が必要）。

## 利用条件の確認

読んだ内容（2026-10-17）:

- ページ脚注に「Documentation Distributed under CC BY 4.0」とあります。`kubernetes/website` の `LICENSE` は CC BY 4.0 です（GitHub の判定も `cc-by-4.0`）。
- CC BY 4.0 は、適切なクレジット、ライセンスへのリンク、変更の有無の表示を求めます。
- **Kubernetes 本体のコードのライセンス（Apache 2.0）を、この文書に適用しません。**

台帳の `license.body` に、出典と加工（抜粋・テキスト化、内容の変更なし）の表記を書きました。**帰属表示の文言、コード例とマニフェストの扱い、第三者の著作物の有無は、人が確認して `third_party_content` を `none` にするまで採用しません。**

## 保持要件

`kind` の対応は、[Python の文書群](public-documents-python.md#保持要件)と同じです。Kubernetes に固有の注意点は次のとおりです。

| 保持するもの | `kind` | 補足 |
|---|---|---|
| YAML・キー・コマンド・フィールド名・API 名 | `code` | `--grace-period=<seconds>`、`secretKeyRef` など。一字も変えない |
| 機能状態・バージョン注記 | `version` | 「Beta since Kubernetes v1.19」、「v1.13以前(v1.13を含む)」。古い版のまま保つ |
| 警告・注意 | `warning` | 「暗号化されずに保存されます」「無期限に実行し続ける可能性があります」など。削らない |
| 推奨・必須の強さ | `strength` | 「推奨します」「すべきです」「必要があります」を保証や必須に変えない |
| 数値・単位・既定値 | `number` | 秒、MiB、0644 と 256 など |
| 推量・計画・伝聞 | `claim` | 「計画されています」は現状の機能ではない。断定にしない |

特に取り違えやすい箇所を保持要件にしました。例: 「Base64 は暗号化手段ではなく」、`limits` だけ指定したときの `requests` の自動設定、メモリーとCPUで超過時の動作が違うこと、強制削除に `--force` が必要なこと。**技術判断が割れた箇所は未解決のままにし、LLM だけで正解を確定しません。**

## 評価の設定

- モードBを明示し、対象読者は生成前に決めて `audience` に書く。`request` も固定する。**対象読者・依頼は未決定。**
- 比較・統計用の `document_id` は台帳の `source_id`、理解問題用は抜粋IDにする（[接続の制約](public-document-evaluation.md#既存ツールとの接続)）。
- 技術文書群として独立に集計する。Python など他の文書群と合算しない。
- 理解問題は抜粋内の前提・制約から答える形にし、一般的な Kubernetes の知識だけで正解できる問いに偏らせない。選択肢の妥当性と正解は人が原文と照合する。
- 古い版の記述を、現行の仕様に合わせて直さない。原文の技術内容を勝手に更新しない。

## 人が行うこと

1. 各 `candidate` について、台帳の本文を原本のページと見比べ、`correspondence` に確認者・確認日を記入する。
2. 利用条件の表記と `third_party_content` を確認する。
3. `preserve` の各項目と `questions` を原文と照合し、`confirmed_by`・`reason`、`verified_by`・`verification_reason` を記入する。修正や削除をしてよい。
4. `kpl-single-schedule` と `ks-tls-protected` を変更不要の対照例にしてよいか判断し、`no_change_reason` を確定する。
5. 採用するものの `status` を `adopted` に変える。`--readiness` の出力が空になるまで繰り返す。
6. 対象読者・依頼を決め、`cases` JSON を作って[計画の手順](public-document-evaluation.md#手順)に進む。
