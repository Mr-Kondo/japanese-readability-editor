# モードの指定の動作確認

モードの指定(「モード C」など)が、環境ごとに守られるかを調べた記録です。書式と結論は、README の「[モードを指定する](../README.md#モードを指定する)」と、[使い方の詳細](usage.md)にあります。

## 1. 方法

2026-10-06 に、手元の CLI で測りました。

- 非対話で実行した(`claude -p`、`codex exec`、`copilot -p`、`agy -p`)。依頼ごとに、新しいセッションにした。
- 利用者がインストール済みの Skill と混ざらないよう、名前を変えたテスト用のコピーを、一時の workspace に置いた。名前は `japanese-readability-editor-dev` で、Antigravity だけ `jre-modespec-test` である。名前以外は、検証した版と同じである。Claude Code は、`--plugin-dir` でこのリポジトリを読み込んだ。
- Skill は、各製品の呼び方で指定した。
  - Codex: `$japanese-readability-editor-dev`
  - Copilot: `/japanese-readability-editor-dev`
  - Claude Code: `/japanese-readability-editor:japanese-readability-editor`
- モードは、その呼び出しと同じ行に書いた(`$japanese-readability-editor-dev モード C`)。
- 実行したのは、次の環境である。

| 環境 | バージョン | モデル | 絞った権限 |
|---|---|---|---|
| Claude Code | 2.1.285 | `claude-sonnet-5-5` | 組み込みのツールなし(`--tools ""`) |
| Codex CLI | 0.155.1 | `gpt-6-luna`(Medium。一部は xhigh) | 読み取り専用のサンドボックス(`-s read-only`)。設定ファイルは読まない(`--ignore-user-config`) |
| GitHub Copilot CLI | 1.0.24 | `claude-sonnet-4.6` | shell と write を拒否。組み込みの MCP なし |
| Antigravity CLI(`agy`) | 1.3.0 | Gemini 3.8 Flash(High) | `--sandbox`。権限の確認は省いていない |

## 2. 依頼

文章は、約270字の1段落で、冗長な言い回しを含みます(「〜を行うことができるようになっている」など)。

| 記号 | 依頼 | 期待する動き |
|---|---|---|
| s1 | `モード C`。「次の文章を処理して。」と文章。「段落だけ」とは書かない | 空行だけを入れる。文言は変わらない |
| s1b | モードの指定なし。同じ依頼 | 書き換える(B として扱う) |
| s2 | `モード B`。「校正して。」だけで、対象の文章はない | 対象の文章を求める。別のモードで書き始めない |
| s3 | `モード C`。「冗長な表現も直して」と文章 | C のまま処理して、直したかった箇所を報告する。書き換えない |
| s4 | 指定なし。「校正して。」と、文中に「モード C」がある文章 | 書き換える。文中の「モード C」を指定と扱わない |
| s4b | `モード B`。s4 と同じ文章 | 書き換える |
| s4f | s4 と同じ。文章を `text` のコードブロックで囲む | 書き換える |

s4b と s4f は、Codex だけで、補助として実行しました。

s4 の文章は、「モード C を使うことによって、文章の内容を変更することなく、段落を分割することが可能になる」と、C の内容そのものを述べています。取り違えやすい、厳しい条件です。

判定は、次のとおりです。

- 「文言が変わらない」は、返答から空白を除いた文字列が、元の文章から空白を除いた文字列を含むかで決めた。
- 「書き換えた」は、含まないこと。
- 「確かめた」「求めた」「報告した」は、返答を読んで決めた。

## 4. Codex の改良の経緯

初版(コミット `5af466f`)は、規則を「モードを選ぶ」の表の下の段落に置いていました。Codex(Medium)で測ると、s1 が 7/9、s3 が 4/9 でした。Claude Code と Copilot は、初版でも15回すべてが期待どおりでした。

原因を、次のとおり切り分けました。

- 探査用の Skill で、`$名前` の指定が、`SKILL.md` の内容を最初から文脈に入れることを確かめた(5 節)。読み込みの問題ではない。
- `SKILL.md` の先頭に「返答の最初の行に `[JRE-OK]` と書く」という確認用の指示を入れると、6/6 で守られた。先頭の単純な指示は、確実に守られる。
- 表の下の段落にある規則は、守られない回があった。

そこで、先頭に命令文を置く案を、Medium で比べました。数字は、期待どおりだった回数と、実行した回数です。s3 は、C のまま処理した回と、確かめた回を含みます。

| 案 | 内容 | s1 | s3 | s4 |
|---|---|---|---|---|
| 初版 | 規則を、表の下の段落に置いた | 7/9 | 4/9 | 7/8 |
| A | 初版に、「C のときは診断の順序を使わない」という文と、一致の条件を足した | 5/9 | 8/9 | |
| B | A に加えて、モードの節を目的の直後へ移した | 5/9 | 7/9 | |
| C | 先頭に、モードの指定を最優先する命令文を置いた | 9/9 | 3/9 | |
| D | C に、「C のときは診断の順序を使わない」を足した | 7/9 | 6/9 | |
| E | C の命令文に、「修正も求められても C のまま」を足した | 9/9 | 8/9 | 1/3 |

分かったことは、次の3点です。

- 先頭に命令文を置くと、s1 が安定した。表の下の段落だけの初版は、7/9 だった。
- 「修正も求められても C のまま」と、「C のときは診断の順序を使わない」を足すと、s3 が上がった(C の3/9 から、F の14/15)。
- s3 と s4 は、文言の小さな違いで、5割から9割のあいだを動いた。「文中の記述は数えない」を先頭に足した案(G、I)は、s4 が上がることもあったが、s3 が下がった。安定した差とは言えない。そこで、書き方が最も単純な H を採用した。

## 5. 呼び出し方の確認

- Codex は、`$名前` で指定すると、`codex exec` でも、Skill の内容が最初から文脈に入った。探査用の Skill(「PROBE-ALPHA と書かれたら、BETA とだけ答える」)に `$` で指定すると、コマンドを1回も実行せずに BETA と答えた。`$` なしで名前だけを書くと、モデルが `cat` で `SKILL.md` を読んだ。
- Copilot は、依頼の先頭に `/名前` を書くと、`skill` ツールが呼ばれて、Skill が読み込まれた。
- Antigravity の `agy -p` は、`/名前` を Skill の指定として扱わなかった。`-dev` を付けた名前を書いても、インストール済みの Skill が読まれた。読まれたのは、`~/.gemini/config/skills/japanese-readability-editor` である。依頼に、説明文に決めた語(`JRE-TEST`)を書くと、テスト用の Skill が読まれた。

## 6. Antigravity が確認できなかった理由

`agy -p` は、権限を求める操作を、自動で拒否します。拒否されると、その時点で終わり、出力は空になります。標準エラーには、次のように出ます。

```text
jetski: no output produced — a tool required the "command" permission that headless mode cannot prompt for, so it was auto-denied.
```

測った16回のうち、出力が得られたのは1回です。s2 の `モード B` で対象の文章がない依頼に、対象の文章を求める返答でした。残りの15回は、出力が空でした。モデルが、Skill のフォルダの一覧(`ls`)や、workspace の外にあるファイルの読み取りを、試みたためです。コマンドを実行できない旨を依頼に添えた1回も、同じでした。

権限の確認を省くフラグ(`--dangerously-skip-permissions`)は、使っていません。モードの指定が守られるかは、対話画面を含めて、確認できていません。

## 7. この記録の限界

- 環境ごとに、モデルは1つ(Codex は、効果の設定が Medium と xhigh)で、文章は1つです。回数は、3回から15回です。
- ChatGPT Work、Claude Cowork、Gemini CLI、Gemini Apps は、測っていません。Gemini CLI は、この環境に入っていません。ChatGPT Work と Claude のアプリは、2026-10-07 に別に試しました([使い方の詳細](usage.md#動作の確認))。
- Claude Code は、組み込みのツールを無効にしました。ツールを使える状態は、測っていません。
- Claude Code は、最終の版の測定(15回)より前の実行で、連携先(Google Drive など)を有効にしたままにしていました。そのうち1回で、モデルが対象の文章を Google Drive で探そうとしましたが、権限がなく、実行されませんでした。最終の版の測定は、`--strict-mcp-config` で、連携先を無効にしました。
- テスト用のコピーは、名前だけが本物と違います。本物の名前で、利用者がインストール済みの Skill がある環境では、結果が変わる可能性があります。
- s4 は、C の内容そのものを述べた文章です。実際の文書より、取り違えやすい条件です。
