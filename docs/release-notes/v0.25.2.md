# v0.25.2

書き換えの数値比較で、数値に隣接する `▲`・`△` と午前・午後を扱うようにした（#219）。

## 変更

- `▲3.2%` から `3.2%` への符号の消失や、`午後3時` から `午前3時` への変更を候補に挙げる。
- `△120円` と `-120円`・`−120円`、`午後3時` と `15時` を同じ値として比べる。
- 正午・深夜と時刻のゼロ埋めをそろえる。`時間` で表す長さや、無効な時刻は変換しない。
- `9時-17時` のように隣接する単位付き範囲を負数と取り違えず、URLの非ASCIIパスを数値として拾わない。
- 日本語パスを含むURLの変更はURL全体の変更として報告する。語と役割の抽出処理は維持する。
- 表示する表記、行番号、コマンドの引数とJSONの構造は維持する。

## 検証と限界

実装前に固定した58ケースでは、意味が変わる14ケースをすべて検出した。同値表記20ケースと対照24ケースの誤警告は0件だった。旧版では、意味が変わるケースの検出は3件、同値表記の誤警告は10件だった。

既存の書き換え78組では数値の警告は増減しなかった。対象表記を含むのは6組に限られる。既存のMarkdown 208文書で変わった抽出結果29件は、符号・時刻の変換に収まった。文脈を確認すると、負数19件と時刻10件だった。数値項目の増減はなかった。

空白で離れた符号・午前午後、範囲の後半に引き継がれる午前午後、「マイナス」という語は解釈しない。数値に隣接する三角記号の箇条書きは、人による確認を要する。漢字・カタカナに続くマイナス記号は負号として認識しない。
伏せ字の識別子はASCIIの `*` を確認した。ほかの記号で伏せた識別子ではハイフンを負号と解釈する場合がある。
`3名-5名` や `3人 -5人` は従来どおり範囲として扱う。空白で区切った負数の列でも、後続のマイナス記号を範囲の区切りと解釈する。

`3時` と `午前3時` は同値だが、`3時` から `午後3時` への変更には警告を出す。午前を補って意味が変わる場合も、その変更は検出しない。日本語パスのURLに空白や句読点なしで本文を続けると、本文の数値もURLの一部として除外する。URLと本文の区切りが必要になる。
このようにURLへ直結した本文だけを直すと、URLの変更として警告する場合もある。
列挙した区切り以外の記号はパスに含める。たとえば全角のコンマ・ピリオドや曲がった引用符では、後続の本文も除外する場合がある。

構成した例と既存資料を使って、従来の動作を損なっていないか確認した。実利用での精度や読者への効果は未確認。
