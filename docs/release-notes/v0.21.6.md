## v0.21.6

`measure.py --extras` に、長い括弧に文を詰めた箇所の指摘 `paren-sentence` を足した（#137）。

### 追加

- 60字以上の括弧（`（）` と `()`）の中に、句点・感嘆符・疑問符で終わる文と、その続きがある箇所を挙げる。入れ子の括弧は対象外。判定ではなく情報である。
- 短い補足（60字未満）と、文が1つだけの括弧（「…である。」）のように閉じ括弧が続くものを含む）は挙げない。末尾も句点で終わる複数文は挙げる。

### 実測（#137）

- このリポジトリの docs と skills の Markdown 55 ファイルで、括弧の中に句点を含む箇所は 56 件（22 ファイル）。長さで絞ると、40字以上が 20 件、60字以上が 8 件、80字以上が 4 件。
- 60字未満の多くは「(名前と版)」「(調査中。未実施)」のような短い注記で、読み飛ばしの害が小さいため、しきい値を 60 字にした。
- 60字以上の 8 件のうち、7 件は補足が長く、本文に出してよい内容を含む。1 件は実行コマンドの引数の列挙で、誤検出に近い。

### レビュー（agy）

- 採用: 末尾も句点で終わる複数文の見逃しを直した。閉じ鉤括弧が続く1文の誤検出を除いた。59字・60字の境界、`！？`、CLI の行まで検証するテストを足した。
- 見送り: しきい値を 40 字に下げる案。40〜59字の 12 件は短い注記が中心で、通知疲れを避けるため 60 字のままにした。

### 限界

- 括弧が入れ子の箇所と、`foo()` のような短い括弧を含む箇所は挙げない。
- 当リポジトリの文書は AI 由来の文が多く、一般の文書の頻度を代表しない。
- 仕分けは作者（私）の読みによる。人の評価は未実施。
- しきい値 60 字は、このリポジトリの分布から決めた値で、他の文書では調整が要るかもしれない。
