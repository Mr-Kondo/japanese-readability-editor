## v0.24.0

「AとBについて」のように、独立した話題を並べた見出しを、本文が別々に書いているなら分ける規則を足した(#174)。「○と△について」の下に、○と△が別々に書かれていても入り混じっていても、読み手は、見出しだけでは、どこまでが○か分からない。利用者の指摘と、対話で決めた方針による。

### 変更

- `references/readability-rules.md` の「見出し」の節に、次を足した。
  - 本文が話題を別々に書いているなら、話題ごとに見出しを分け、元と同じ階層に並べる。「について」で終わる見出しに限らず、「と・や・および」で並べた見出しが対象。
  - 本文が○、△の順なら、境界に見出しを足すだけにする。入り混じっているなら、文の言い回しは変えず、話題ごとにまとめる並べ替えだけをして、変更報告に書く。番号つきの見出しは番号を振り直し、壊れる参照は報告する。
  - 本文が比較・関係・使い分けを論じているなら、分けず、見出しに中身を書く(「○と△の違い」)。「関係」のような曖昧な語の見出しは、節の冒頭の文を、その中身を言う文にする。
  - 「検索と置換」のように1組で扱われる語は、本文が別々の話題として書いているときだけ分ける。判断がつかなければ直さず、報告する。
  - 見出しの文言の指定がある依頼と Paragraph-only モードでは、見出しを変えず、報告する。
- `SKILL.md` の見出しの項目に、同じ内容の短い節を足した。行数は変えていない(上限の175行)。
- `assets/examples.md` に、例34(分ける・分けない)を足した。
- 機械検出(`compare_rewrite.py`、`measure.py`)は足していない。別の話題かどうかは本文を読む判断で、「入力と出力」のような1組の語を誤検出しやすいため。

### 影響を受ける使い方

- 話題を並べた見出しを持つ文書をモード B で推敲すると、見出しが増え、後ろの番号が振り直される場合がある。見出しの文言を指定する依頼と、モード C では変わらない。

### 実測(2026-11-14)

旧版(v0.23.0)と新版を、自作の9本の短い文書で、各3回(54出力)比べた。計画は生成の前にコミットした([evals/heading-split.md](../../evals/heading-split.md))。

- 本文が別々の話題の見出し3本(9出力)を、旧版は0件、新版は9件すべて分けた。番号つきの見出しは、新版の3出力とも1から連続した。
- 比較・使い分け・1組の語・曖昧な語の見出し(各1本、計12出力)、見出しの文言の指定、モード C では、新版も分けなかった。見出しの文言は、見出しの指定とモード C では全件で保った。そのほかでは、末尾の「について」が削られた出力がある(h05 は両版の全件、h04 は新版の1件、h09 は旧版の全件)。
- 保つ語(数値・条件・用語)の欠落は、新版の27出力で0件。
- モード C の1項目は、計画の数え方が出力の体裁を測っていたため、結果を見てから数え方を直し、h08 だけを測り直した。1回目の判定は記録に残している。詳細は [evals/heading-split-result.md](../../evals/heading-split-result.md)。

### 限界

- 合成した9本で、実文書での頻度や効果は測っていない。モデルは `sonnet`(medium)の1つだけ。
- 「関係」のような曖昧な語の見出しの冒頭を言い切る直し方は、新版で3件中1件、旧版で0件だった。効果は確かめられていない。
- 「直さず報告する」場面の報告は、h08 の1件のほかは測れていない。意味の保持は、実行者が読んで確かめた。別の採点者による盲検の採点はしていない。
