## v0.21.0

意味が分かれる箇所の問い直しと、推敲後の対象・条件・状態の照合を明確にした。

### 変更

- 一般文書の A/B で、意味を左右する読みを選ぶ必要がある場合は、その関係だけを先に尋ねる。質問で未確認の対象を事実として導入せず、確認済みの意味も聞き直さない。
- 必要な場合だけ読み方の違いを示し、回答に基づいて案を直す。明確な文まで形式的な承認待ちにしない。
- 本文のみの指定や対話できない場合は、不明部分を原文のまま残す。意図的な曖昧さも保つ。
- 原文・資料の必要な主張と修正文を照合する。同じ用語が残ることや検査の指摘がないことだけで、意味を保てたと判断しない。
- 短さ・文数・体言止めと必要条件が両立しないときは、条件や形式を黙って変えず、調整点を確認する。
- 公開する例と評価入力は新規の人工例だけとした。

### 検証と限界

- 公開対象だけのソースで全体検証を実行し、1,025件中1,012件成功・13件スキップ。ZIPとSHA-256、隔離配置での導入・更新・正本照合・削除を確認した。
- 人工8ケースと確認後の応答を、変更前・初稿・補修後・最終版で確認した。比較対象を問い直す挙動を確認したが、不要な追加質問は残っており、十分に抑えられたとは判定していない。
- 検証の方法と実施範囲は、[意味確認の評価記録](https://github.com/Mr-Kondo/japanese-readability-editor/blob/main/evals/meaning-confirmation-result.md)に記載する。構造・配布物の検証と、モデルが指示に従うかの評価は区別する。
- Codex・Claude Code・Gemini Antigravityでの今回の版の実呼び出し、Windows実機、独立した人手評価は未実施。既存のインストール済みコピーは自動更新しない。
