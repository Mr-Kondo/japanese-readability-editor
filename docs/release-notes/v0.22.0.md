## v0.22.0

導入を `npx skills add` に一本化し、`tools/install.py` と `tools/uninstall.py` を廃止した（#156）。Skill 本体（`skills/japanese-readability-editor/`）の内容は変えていない。

### 変更（導入手順が変わる）

- `tools/install.py`、`tools/uninstall.py` と、そのテストを削除した。導入は `npx skills add <リポジトリ> -a <環境> -g`、削除は `npx skills remove japanese-readability-editor -g` を使う。
- 失う機能: リポジトリへの直接リンク（`--link`。開発時は `ln -s` を使う）、上書き前の退避、`--dry-run`、重複の警告。複数環境への導入は、`-a` に並べて続けられる。
- `package.py` が作る OpenCode・Hermes 向けの `INSTALL.md` は、`npx skills add ./japanese-readability-editor -a <環境>` と、手動のコピーの2本にした。
- 配置先の表と解決は `skill_env.py` に移した。`verify_install.py` の重複検出と、`skill_env.py` の同名 Skill の探索は削除した。

### 移行（`install.py` で入れていた人）

- `install.py` で入れた複製やリンクは、`npx skills` では消えない。古いものを削除してから `npx skills add` で入れ直す（手順は `docs/installation.md`）。同じ Skill が2か所にあると、OpenCode と Hermes は片方しか使わない。
- Antigravity のユーザー全体の配置先（`~/.gemini/config/skills/`、`~/.gemini/antigravity-cli/skills/`）には、`npx skills` は入れない。手動でコピーする。

### 実測（2026-11-10、macOS、skills 1.7.6、隔離したホーム）

- Codex、OpenCode、Claude Code、Hermes は、`install.py` と同じ場所に入った。同名への再導入は上書きされ、`npx skills remove` も動いた。`verify_install.py` は、入れた2か所で 0 error、0 warning だった。
- 未確認: GitHub からの実インストール、`npx skills update`、Hermes のプロファイルを使った入れ先。

詳細は `adr/2026-11-10-remove-install-py.md`。
