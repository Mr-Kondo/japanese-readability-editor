## v0.23.0

入力ファイルを読むスクリプトが、読んでよい場所を狭めた（#166）。推敲する文書に紛れ込んだ指示で、鍵や認証のファイルが読まれ、中身が出力に載る経路を減らすため。考え方は参考先 nanaism/yomiyasu の v3.0.0 に由来し、実装はこちらの構成で書いた。

### 変更（読めない場合が増える）

- `measure.py`、`compare_rewrite.py`、`check_kokugo.py`（`--glossary` を含む）、`check_fiction.py`（`--settings` を含む）、`verify_preservation.py`、`make_feedback.py`、`make_change_report.py` は、標準入力（`-`）と、作業フォルダまたは一時フォルダの下のファイルだけを読む。
- その下の部分に「.」で始まる名前（`.env`、`.git`、`.ssh` など）を含むパスは、読まずに終了コード 2 で止まる。シンボリックリンクは、リンク先で判定する。
- `measure.py` にフォルダを渡したときの走査は、「.」で始まるフォルダとファイルを数えない。フォルダの引数も、走査の前に検査する。
- 判定は、新しい共通のモジュール `scripts/input_guard.py` に置いた。書き換え前の文章を一時フォルダへ退避する手順（`references/scripts.md`）は、そのまま使える。
- 止まったときは、文書を作業フォルダの「.」で始まらない名前へ写すか、標準入力で渡す。

### 影響を受ける使い方

- 作業フォルダの外にある文書（別のフォルダの原稿など）、`.github/` や `.claude/` の下の文書を直接渡す使い方は、止まるようになった。写すか標準入力で渡す。

### 実測（出力に載る内容。2026-11-12）

- 本文の断片は出力に載る。`compare_rewrite.py` は数値などの該当箇所、`check_kokugo.py` は該当表記、`measure.py --locate` は段落の冒頭を出す。鍵の値が本文にあれば、出力に出る。
- 試験は、各スクリプトが「.」で始まるファイルと範囲外のファイルで止まり、終了コード 2 と理由を返し、中身を出さないことを確かめる。

### 限界

- 文書内の指示に従うエージェントの動きは防げない。スクリプトが読む範囲を狭めるだけである。
- 一時フォルダ全体を許すため、そこに「.」なしの名前で置かれた他のファイルは読める。
- 大文字小文字を区別しないファイルシステムで、作業フォルダと大文字小文字だけが違うパスは、読まない側に倒れる。
- Docker や SSH など、作業フォルダの意味が環境で違う場合は、未確認。
