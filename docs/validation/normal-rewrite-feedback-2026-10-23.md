# 通常推敲での変化の記録(2026-10-23)

## 問題と修正

利用者の報告は、Windows の Codex に通常の文章推敲を依頼してもフィードバック用ファイルが出ない、というものだった。v0.20.0 の `SKILL.md` と `references/change-report.md` には、変化の記録を求められたときだけ実行し、通常は実行しない指示があった。保存処理の Windows 固有障害は確認していない。

モード B の照合に続き、最終結果から `make_change_report.py` を実行し、保存を確認してから一時ファイルを削除する手順に変えた。既存の記録処理を使い、保存の実装は変更していない。

## 手元の Codex による確認

- 環境: macOS、Codex CLI 0.163.0、モデル `gpt-6-luna`。一時作業フォルダ、`workspace-write`。既定の記録先への書き込みを `--add-dir` で許可した。
- 読み込み: 対象の `SKILL.md` を絶対パスで明示した。インストール済みスキルの自動選択は検証していない。
- 依頼: モード B で読みやすくし、完成した文章だけを返す。記録の作成は依頼文に書かなかった。
- 入力: 「管理者の承認が得られた場合においては、処理を30分以内に実行することが可能です。ただし、休日の場合は翌営業日に実行します。」(人工例)
- 観測: JSONL の `command_execution` イベントで `compare_rewrite.py` と `make_change_report.py --original before.md --result after.md --mode B` の実行を確認した。後者には既定と同じ保存先を `--out-dir` でも渡していた。
- 保存: `saved_to` が指す新規 JSON を実際に読み、`kind=jre-change-report`、`context.mode=B`、原文・結果・引用を持たない形式であることを確認した。
- 返答: 推敲後の本文だけで、記録の内容は表示されなかった。
- 後片付け: この実行で作った記録と一時作業フォルダを削除した。

この1回の成功は、すべての呼び出しでの実行を保証しない。利用者の Windows 端末での実呼び出し、モード A/C/D の自動記録、推敲品質の比較は未検証。スクリプトを実行できない環境や保存権限がない環境では、記録は作れない。
