## Decisions for this implementation

- Preserve the names A/B/C, explicit mode selection, and existing script defaults. Keep the original wording and ask for clarification when multiple mode instructions conflict.
- Separate D's new generation from revision that retains existing content, and branch it away from general-document shortening and metaphor explanations.
- Do not require a full management set for small requests. Long-form notes are optional; prohibit automatic overwriting of manuscripts and settings.
- Limit checks for specified settings to simple string matching. Candidates for numbers, parentheses, and notation are aids for human review.
- Do not introduce Codex-specific APIs into the core. Preserve existing distribution destinations, OpenCode/Hermes adapters, and Agency for Cultural Affairs-related features.

## Verification limitations

Deterministic tests check the CLI, data, retention, and distribution. Model behavior is handled separately in [evaluation cases and run records](../../../../evals/README.md). An implementer's self-review does not replace an independent model run or human literary evaluation. Do not treat exact matching of an entire piece of fiction as the answer key; consider style, point of view and knowledge, disclosure, confusion, and fit to the request. Do not treat creative-writing theories in reference materials as universal laws of literature.
