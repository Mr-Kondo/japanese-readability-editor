# 日本語の読みやすさの設計原則と参照元

## 要点

- 診断は内容と論理から始め、漢字は後回しにする。
- 段落200字以上、文46字以上などは見直しの候補であり、合否の基準ではない。
- スクリプトは候補と文字列の一致を確かめるだけで、書き換えの判断は Agent が行う。
- 書き換え後は、数値、条件の範囲、否定、主体などを原文と比べ、違えば戻す。
- 二重否定や「その他すべての場合」などの残余条件は、原則として変えない。

## 目的

Skill の設計原則と、原則を作る際に参照した記事とプロジェクトを示します。原文は転載せず、原則と手順として再構成しました。

## アプローチ

| 番号 | 原則                                                                                                   |
| ---- | ------------------------------------------------------------------------------------------------------ |
| 1    | 内容と論理、段落、文、構造、論理関係、予測可能性、主体、直訳調、抽象語、冗長さ、漢字の順に診断する     |
| 2    | 段落200字以上、文46字以上（30〜45字は目安）、20字未満の文が3文以上続く箇所は見直しの候補               |
| 3    | 長いだけの段落は、語を変えず話題の区切りで分ける。空白以外の文字が変わらないことをスクリプトで確かめる |
| 4    | 書き換えの判断は Agent が行う。スクリプトは候補と文字列の一致の確認だけ                                |
| 5    | 数値、条件の範囲、否定の数、主張の強さ、強調、主体、文体を原文と比べる                                 |
| 6    | 二重否定や残余条件は変えない                                                                           |

| Zenn: lotation        | 記事                      | 同上                                                             |

## 限界・未確認

- 文化庁の国語の表記・用法の基準に基づく検査は、内閣告示と内閣訓令の条件を満たす場合だけ `error` とする。勧告、報告、答申は `recommendation` または `needs_context` に限る。
- 文の長さの目安は、この Skill の運用上の目安であり、文化庁の基準ではない。
- 敬語、ローマ字、字体、未登録語は、確認済みとして扱わない。
- natural-japanese の AI らしさの採点、文体の類型、サブエージェントによる編集は採らない。標準ライブラリだけで単一の SKILL.md として動かすため。
